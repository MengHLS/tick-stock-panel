| 口径 | 全轴 | 窗内 | `ISO \ 错法` | `错法 \ ISO` |

| **ISO 年-周（正确）** | 452 | 376 | — | — |

| 自然年 + `%W`（另一种「自然周」写法） | 454 | 378 | ∅ = **0** | {2019-12-31, 2024-12-31} = **2** |

裁定：
1. 契约必须**写死**「错法 = 自然年 + ISO 周号（`iso_week` 配 `calendar_year`）」，不得只写「自然年+周号」；`%W` 变体另立一行，不许混用。
2. **断言只比集合**：窗内两种口径计数都是 **376**，用计数做判据**零鉴别力**。
3. 全轴 **3+2** 成立；窗内 **2+2**（`2019-01-04` 落在窗口之前）。同一判据要同时给全轴与窗内两套，不许只给一个。
4. **撤回**：我上一轮「跨年双向各 3 天」中的第二侧 3 → **2**，整句作废；`2026-11-06` 在**两种口径都算** week_end，不是差集元素。
5. **撤回**独立审核「3+2 不可复现」的结论：其方法是去实现里找 `week_rule` 开关，而该「错法」本应在核对脚本内自算，生产实现里本来就不该有该开关。
