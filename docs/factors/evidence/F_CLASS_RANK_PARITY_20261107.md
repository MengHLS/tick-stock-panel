## 2. 判读

1. **8 对全部 `< 1e-12`。** 7 只逐位 **0.0**；`uf_vol60` 在 20×250 子样上 `2.7755575615628914e-17`（1 ULP 级，小于全帧的 `1.1102230246251565e-16`，量级不随子样放大）。
2. **名次零漂移。** 末交易日（2026-10-30）全截面 average 名次：8 对 `rank_change_max` 全 **0.0**、被换位 **0** 只、两侧 tie 组数**逐一相同**（如 `prior_high_250` 3,155 只中 2,891 个不同名次，tie 结构两侧一致）；`in_universe` 截面（1,716–1,723 只，随各因子空值而异）与 20 只子样同样全 0。
3. **250 个交易日逐日复算，名次变化最大值仍 0.0、有换位的交易日 0 天。** 即 1 ULP **没有**在任何一天改变过任何一只的名次，也没有拆开/合并任何 tie 组。
4. **`uf_vol60` 全帧复测**（本台账 16:20，独立于既有证据）：`max_abs_diff = 1.1102230246251565e-16`、`n = 6,220,352`（含预热段）、非零差 4,781,712 行、null 不一致 0 —— 与 `F_CLASS_PARITY_20261107.json`（评估窗口 `n = 5,469,335`、同一 `max_abs_diff`）一致，1 ULP 稳定复现，**未消除，也不应为消除它去改任何一侧定义**（两侧定义同源于契约 §7.1，差异在实现层 `pct_change` 写法，K7）。
5. **既有证据的更正**：任务书说「5 个 `uf_prior_*` 一份对账都没有」—— 实测不成立，`F_CLASS_PARITY_20261107.json` 里 8 只**全有**全帧对账（`prior_*` 全 `0.0`、n≈5.37M–5.50M），**但那份证据没有名次列、也不是 20×250 的 F-A3 形状**。本文件补的正是这两项，不是从零开始。
