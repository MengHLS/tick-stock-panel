# 首板事件自动因子区分设计

日期：2026-10-29

## 1. 意图

在现有因子系统中，以平台口径首板事件为样本，自动寻找能在 T 日收盘时
区分后续表现强弱的现有因子，并通过独立扩展页面展示：

- 自动筛选出的单因子与 1-3 维因子规则；
- 规则的训练期选择依据、验证期表现、覆盖率与样本数；
- 每条规则命中的首板事件及后续最高收益、收盘收益、最大不利波动；
- 明确的数据质量、未来函数与历史制度限制。

本功能是研究分类工具，不自动创建策略、不自动下单，也不把历史区分能力
表述为因果或未来收益保证。

## 2. 已确认口径

### 2.1 事件与特征时点

- 首板事件：`consecutive_limit_ups == 1`，沿用平台现有口径。
- 特征只使用 T 日及之前已经可知的数据。
- 首板身份、历史 ST 状态和早期板块涨跌幅制度目前不可完整认证，页面必须
  持续显示 `平台口径首板、历史制度未认证`。
- 分类提供两个明确的特征快照：
  - `D_minus_1`：T-1 收盘可知，适合盘前观察；
  - `D_close`：T 日收盘可知，动作最早只能在 T+1。

### 2.2 收益标签

主标签：

```text
mfe_20d = max(high[T+1..T+20]) / open[T+1] - 1
strong = mfe_20d >= 0.20
```

辅助标签：

```text
mfe_5d = max(high[T+1..T+5]) / open[T+1] - 1
close_return_5d = close[T+5] / open[T+1] - 1
mae_5d = min(low[T+1..T+5]) / open[T+1] - 1

mfe_10d = max(high[T+1..T+10]) / open[T+1] - 1
close_return_10d = close[T+10] / open[T+1] - 1
mae_10d = min(low[T+1..T+10]) / open[T+1] - 1

close_return_20d = close[T+20] / open[T+1] - 1
mae_20d = min(low[T+1..T+20]) / open[T+1] - 1
stop_touched = mae_20d <= -0.08
```

设计取舍：

- 以 T+1 开盘为收益基准，避免把 T 日收盘后才知道的信号当成可成交价格。
- 自动分类标签仍固定使用 20 日最高收益；5 日和 10 日只作为辅助收益结果，
  不参与当前规则选择。
- 每个窗口的最高收益衡量机会大小，期末收益衡量持有结果，最大不利波动
  衡量路径风险；三者不能合并成一个不可解释的评分。
- 不足 20 个可观察交易日的事件标记 `right_censored`，默认不参与自动发现，
  但仍在事件明细中展示原因。
- T+1 开盘无法成交、缺少 T+1 行情或价格无效的事件标记为
  `entry_unavailable`，不参与训练和验证。

## 3. 目标、非目标与反目标

### 3.1 目标

- 自动从现有因子中筛选对 `strong` 有区分能力的候选。
- 用可解释规则替代黑盒模型。
- 只在训练期选择因子和阈值，验证期只做评估。
- 页面可以追踪任一规则对应的原始事件与收益标签。
- 实现为独立前后端扩展，不修改核心挖掘引擎和核心页面。

### 3.2 非目标

- 不新增因子计算逻辑；所有因子复用注册表和既有物化管线。
- 不把结果自动转成策略、信号、监控规则或模拟盘规则。
- 不执行分钟级盘中判断。
- 不承诺寻找稳定盈利策略。
- 不自动填充缺失财务、历史股本、历史 ST 或行业/概念历史归属。

### 3.3 反目标

- 使用 T+1 及以后的数据构造 T 日特征。
- 在同一批数据上选择因子和报告最终表现而不做验证期隔离。
- 用类别准确率代替基准命中率与提升倍数。
- 仅展示最高收益而隐藏最大回撤或不可成交情况。
- 把当前流通股本派生的换手率、当前行业/概念快照包装成历史时点因子。

## 4. 方案比较

### 方案 A：直接复用现有自动挖掘

现有 `backend/app/services/auto_mining.py` 与
`backend/app/backtest/mining_runtime.py` 面向全市场未来收益的截面 IC、
组合搜索和策略回测，目标列不是首板事件的条件收益。

结论：不采用。直接复用会回答“哪些因子能选股”，而不是“哪些因子能区分
首板事件”。

### 方案 B：首板事件条件的有监督因子发现

以 `strong` 为二分类标签，在首板事件样本上筛选单因子 AUC，再在训练期内
搜索有限的 1-3 维分位规则，最后在时间验证期评估。

结论：采用。它直接回答问题，可解释、可回查，并能复用现有因子物化。

### 方案 C：无监督聚类

对事件因子向量标准化后聚类，自动得到若干首板画像。

结论：首版不采用。聚类不依赖收益标签，得到的类别不一定对应后续强弱；
簇的数量、命名与稳定性也缺少现成验收口径。

## 5. 实现分级

该功能属于 L2 扩展：

- 后端新增 `backend/app/custom/firstboard_discovery/` 扩展包并注册独立路由；
- 前端新增 `frontend/src/custom/firstboard-discovery/extension.tsx` 路由与导航；
- 复用 `BacktestEngine`、因子注册表、`FactorBacktestService` 的因子物化路径；
- 不修改 `backend/app/main.py`、核心挖掘引擎、核心路由或核心页面。

扩展失败时只禁用本页，不影响应用启动和既有功能。

## 6. 后端设计

### 6.1 服务边界

新增 `FirstboardDiscoveryService`，负责：

1. 生成事件样本；
2. 计算未来收益标签；
3. 物化候选因子；
4. 生成训练/验证切分；
5. 执行单因子筛选与规则搜索；
6. 返回可序列化快照。

服务每次完成新计算后，将报告和全部事件原子写入：

```text
<data_dir>/user_data/firstboard_discovery/runs/<run_id>/
  report.json
  events.parquet
  metadata.json
```

`metadata.json` 是完整写入标记；旧版 `events.jsonl.gz` 记录保持只读兼容。
扩展 `startup()` 从 `ExtensionContext.repository` 和 `ExtensionContext.data_dir`
构造服务；路由不直接依赖整个 `app.state`。

### 6.2 样本加载

请求参数：

```text
start: 事件起始日
end: 事件截止日
horizon: 固定 20，首版不接受任意大窗口
strong_threshold: 默认 0.20
snapshot_mode: D_minus_1 | D_close | both
```

加载范围：

- 起始日前留出至少 270 个自然日，覆盖 250 根预热；
- 截止日后加载到已有数据的最后一天，用于形成未来标签；
- 只加载股票资产；
- 只加载所需物理列和因子依赖，避免全表投影。

首板事件仍从 `consecutive_limit_ups == 1` 读取。因子通过
`FactorBacktestService._compute_missing_factors` 或同一公开物化入口计算，
禁止另写指标实现。

### 6.3 候选因子范围

默认从注册表股票因子中动态生成，但首版排除以下组：

- 财务因子：本地财务目录可能为空，覆盖不足时自动失败；
- 依赖当前流通股本、且没有历史股本覆盖的换手率派生因子：
  `turnover_rate`、`turnover_ratio_5d`、`turnover_z_60d`、
  `turnover_mean_20d`、`turnover_std_20d`、`log_float_mv`；
- `ext_*` 扩展因子：除非其数据源明确具备历史时序，否则不默认进入；
- `D_close` 模式的 `change_pct`：在首板日与标签高度同义；
- 任何无法在事件日形成非空前值的依赖。

`D_minus_1` 和 `D_close` 分开评分，不把同一因子的两个时点合并成一条规则。

### 6.4 未来标签与质量标记

每个事件生成：

```text
event_id, symbol, name, date
entry_date, entry_open
sessions_observed, right_censored
entry_unavailable, entry_limit_locked
scale_break_suspected
mfe_20d, close_return_20d, mae_20d, stop_touched
strong
```

处理规则：

- T+1 使用同一 symbol 的下一条有效日 K；
- 入场基准为 T+1 复权 open；
- T+1 raw open 达到涨停判定价时标记 `entry_limit_locked`，首版从训练和
  验证中排除；
- 收益窗口跨复权比异常跳变时标记 `scale_break_suspected`，默认排除并显示
  原因；
- 缺少所需价格、非正价格或无 T+1 行时标记 `entry_unavailable`；
- 所有排除原因在报告元数据中计数，不允许静默丢弃。

### 6.5 时间切分

- 按唯一事件交易日排序，前 70% 日期为训练期，后 30% 为验证期。
- 不随机打乱事件。
- 同一交易日的所有事件完整落入同一侧。
- 训练事件少于 120 或验证事件少于 60，或少数类样本不足时，返回
  `insufficient_sample`，不生成自动规则。
- 同一年度内的规则稳定性作为结果字段展示，不参与首版自动选优。

### 6.6 单因子筛选

对每个候选因子：

1. 只用非空值计算；
2. 覆盖率低于 60% 不进入排名；
3. 计算二分类 AUC；
4. 方向由 AUC 与 0.5 的关系决定；
5. 对训练期 p 值执行 BH-FDR；
6. 按 `|AUC - 0.5|` 排序，最多保留 8 个因子进入组合规则搜索；
7. 验证期只计算 AUC、方向和覆盖率，不反馈修改候选。

AUC 使用秩和/Mann-Whitney 口径，处理并列值；不新增 SciPy 依赖。

### 6.7 规则搜索

首版只生成可解释的分位规则：

- 1 维：单因子高侧或低侧分位区间；
- 2 维：前 4 个因子中两两组合，使用三分位桶；
- 3 维：仅当训练事件不少于 600 时启用，使用前 3 个因子和三分位桶。

限制：

- 每个规则在训练期至少命中 30 个事件；
- 在验证期至少命中 15 个事件，否则只展示但不判定为可用；
- 只用训练期选择规则和阈值；
- 验证期指标不参与规则排名；
- 最终最多返回 8 条规则；
- 规则名称由因子标签、方向、阈值组成，不使用自动生成的模糊类别名。

规则指标：

```text
hit_count
coverage
base_strong_rate
rule_strong_rate
lift = rule_strong_rate / base_strong_rate
wilson_lower_bound
train_auc
validation_auc
validation_strong_rate
validation_lift
mean_mfe_20d
mean_close_return_20d
mean_mae_20d
```

排序只使用训练期指标；页面必须同时显示验证期指标。

### 6.8 缓存与并发

- 报告是不可变快照，按以下键缓存：
  - enriched generation；
  - 事件起止日期；
  - horizon 和 strong threshold；
  - snapshot mode；
  - 候选因子清单及版本；
  - 算法版本。
- 内存缓存最多保留 4 份，使用锁只保护读取和原子替换，不在锁内计算。
- 新计算成功后先校验 generation 未变化，再持久化报告和全量事件；写入失败
  不进入内存缓存。
- 计算先读取 generation，完成后校验未变化；变化时返回可重试错误，不返回
  混合世代结果。
- 前端请求超时提高到 300 秒，页面显示明确的加载阶段和耗时。

### 6.9 API

扩展路由前缀：

```text
/api/custom/firstboard-discovery
```

端点：

```text
GET /report
GET /events
GET /runs
GET /runs/{run_id}/report
GET /runs/{run_id}/events
```

`/report` 返回：

- 请求参数与数据 generation；
- 样本账：事件数、可用数、右截断、不可成交、复权异常；
- 训练/验证区间与事件数；
- 基准强首板率；
- 单因子排名；
- 规则排名；
- 数据质量限制与算法版本。

`/events` 返回分页事件明细，可附加：

```text
rule_id
page
page_size
```

分页上限 200。事件明细不进入 `/report`，避免大响应。

`/runs` 返回按保存时间倒序的记录摘要；历史报告与事件直接读取持久化快照，
不重新触发计算。

## 7. 前端设计

### 7.1 接入方式

新增源码扩展：

```text
frontend/src/custom/firstboard-discovery/extension.tsx
```

注册：

```text
route: /firstboard-discovery
navigation: 首板因子区分
```

页面使用单一命名空间内的请求函数和查询键，不修改核心 `api.ts` 与
`queryKeys.ts`。请求 URL 不散落在多个组件中。

### 7.2 页面结构

1. 顶部控制区
   - 起止日期；
   - 快照选择：T-1 / T 收盘 / 两者；
   - 固定显示 20 日和 20%；
   - “重新发现”按钮。

2. 样本账
   - 首板事件总数；
   - 可评估事件数；
   - 强首板基准率；
   - 训练/验证事件数；
   - 右截断、不可成交、复权异常数量。

3. 自动发现结果
   - 单因子表：因子、快照、方向、覆盖率、训练 AUC、验证 AUC、q 值；
   - 规则表：条件、命中数、训练提升、验证强首板率、验证提升、最大回撤均值。

4. 历史记录
   - 展示保存时间、事件区间、可评估事件数；
   - 选择历史记录后直接载入报告和全量事件；
   - 新算结果自动保存并刷新历史列表。

5. 事件明细
   - 股票、事件日、T+1 入场日；
   - 可切换 5 / 10 / 20 日窗口；
   - 分别展示最高收益、期末收益、最大不利波动；
   - 命中规则；
   - 数据质量徽标；
   - 点击规则后过滤事件。

5. 固定风险提示
   - 平台口径首板，历史制度未认证；
   - 自动选择在训练期完成，验证期仅评估；
   - 最高收益不等于可兑现收益；
   - 结果不构成投资建议。

### 7.3 状态

必须覆盖：

- 加载中：显示当前阶段，不展示旧区间的规则；
- 空数据；
- 样本不足；
- 后端数据世代变化，可重试；
- API 错误；
- 规则无命中；
- 移动端表格横向滚动与卡片重排。

## 9. 兼容性与升级风险

- 不改变现有 API、缓存、策略、信号、监控或数据文件格式。
- 新页面通过现有扩展注册表加载，删除扩展目录即可卸载。
- 后端扩展加载失败时只禁用自身。
- 页面默认应遵循现有扩展页的“新装用户隐藏、用户手动开启”规则。
- 上游 `KlineRepository`、`BacktestEngine` 或因子注册表变更时，优先复核：
  - enriched 物理列；
  - `consecutive_limit_ups` 口径；
  - 因子物化入口；
  - generation 语义。

## 10. 风险与降级

- 历史首板身份未认证：结果只用于研究，不进入正式统计或自动交易。
- 20% 阈值是研究选择，不是市场规律：页面显示连续收益分布与基准率。
- 20 日窗口重叠可能夸大稳定性：按交易日切分，并在验证期独立报告。
- 自动搜索存在多重比较：训练期 BH-FDR，组合规则数量上限固定。
- 最高收益可能不可兑现：同时展示收盘收益、最大不利波动和不可成交标记。
- 数据覆盖不足：返回样本账与原因，不用空值或零值替代。

## 11. 实施边界

首版只实现上述报告、规则和事件浏览。以下内容不在首版：

- 把发现的规则一键发布成策略或监控规则；
- 黑盒分类器、神经网络或自动簇命名；
- 盘中实时分类；
- 自动修改因子的可用/停用状态；
- 自动参数优化到“最佳收益”或选择最佳阈值。

## 12. 完成标准

- 页面与 API 可在不改核心入口的情况下加载和卸载。
- 使用现有因子物化路径，不重复实现指标。
- 自动发现只使用训练期选择，验证期独立报告。
- 每个结果都能追踪到具体首板事件与收益标签。
- 所有未来标签、截断、不可成交和制度限制均有明确展示。
- 后端定向测试、Ruff、前端构建和 `git diff --check` 通过。
