## 3. 逐项结论

### 3.1 确证通过（本地一致性）

| 检查 | 结果 |
|---|---|
| 分区与行级一致性 | 9,780,842 行中重复（同分区同证券）**0**、行日期与分区日期不符 **0**、无法解析日期 **0**、非 ISO 分区名 **0**、非交易日分区 **0**、未来分区 **0** |
| 交易日历对齐 | 面板窗口内：指数日历缺失面板分区 **0**，面板多出非交易日分区 **0**。**但这只证明两家供应商数据彼此一致，不等于交易所日历属实**（两侧同源） |
| 原始/复权分区对齐 | 2,141 = 2,141，双向差集为 **0** |
| 复权因子契约 | 按 `backend/app/indicators/price_quality.py` 的 `0.2 ≤ ex_factor ≤ 5.0`：重复对 **0**、同股同日冲突 **0**、越界或非有限值 **0**、未来日期 **0**；实测区间 1.0 ~ 3.5814 |
| ST 表完整性 | 同股同日冲突 **0**，无不可解析行 |
| 行业快照完整性 | 6 个分区内重复 **0**、同一证券同日两个行业 **0**、空分区 **0**、未来分区 **0**、行业列正确解析为 `所属同花顺行业` |
| 零价行 | 9,780,842 行中 `open==0 且 high==0` **0 行**，`open`/`high` 单侧为零 **0 行**，负价 **0 行** |

零价行这一条只能证明一件事：**本地面板中不存在 `open==0 且 high==0` 这种行形态**。项目下游（`backend/app/indicators/pipeline.py`）把该形态当作「停牌日」过滤，说明项目预期的停牌表示法是「行存在、价格为零」；而本地面板里这种行一行都没有，同时还存在 43,503 个「证券×交易日」缺口。这两条合起来只够支撑一个否定结论：**本地数据无法用来识别停牌日**。

它**不能**用来确定这些行是在哪一环消失的。供应商未提供、采集端过滤、入库前清洗、入库后删除，这四种可能都能产生「零价行为 0 + 存在缺口」的观测结果；区分它们需要来源原始数据、采集/清洗日志或入库代码路径的对照。本轮审计在数据根内没有找到这类对照材料（停牌表同样不存在），代码侧只读了 `pipeline.py` 的消费约定，未审计采集与入库链路。因此在拿到这类证据之前，§3.3 的缺口成因与「删除发生在哪一阶段」一律记为 `unknown`，本文不作「入库时整行删除」之类的过程性断言。

### 3.2 确证异常（退出码 1 的来源）

1. **`instruments` 有 3 行没有上市日期**：`002525.SZ`、`300060.SZ`、`600849.SH`（5,536 行中 3 行 `listing_date` 为空）。
2. **行业快照含非交易日分区**：`date=2026-11-01` 是周日（当周仅 5 个交易日）。若按日期直接 join 行业表，会在非交易日注入伪日期/空值行。
3. **行业时点历史深度不足**：6 个自然日、5 个交易日，只占面板 2,141 个交易日的 **0.23%**。任何跨越 2026-11-01 之前的行业轮动回测，都没有对应的时点成分。

### 3.3 标为 unknown（不是通过）

| 项 | 实测事实 | 为什么仍是未知 |
|---|---|---|
| 证券生命周期 / 停牌 | 2,083 只证券在自身首末日期之间存在缺口，共 **43,503 个「证券×交易日」**；**241 只**在面板最后交易日之前停止更新；单只最差 `000670.SZ` 缺 612 个交易日 | 本地无停牌表、无退市/重新上市记录，缺口无法归因为「停牌」「退市」还是「采集缺失」。缺 612 天与「长期停牌」现象一致，但一致不等于确证；反过来，缺口本身也**不是**停牌的证据 |
| 复权因子覆盖 | 5,813 只面板证券中 **616 只**完全没有因子行（如 `000004.SZ`） | 因子是按除权事件写的，没有公司行为台账就不能断言「无因子 = 无除权」 |
| ST 历史 | 面板窗口 2,141 个交易日中，**793 天**没有任何 ST 行；其中 **239 天**早于首条记录（2019-01-01），**6 天**晚于末条记录（2026-10-29） | 该表只记变更日，无记录的交易日无法区分「当日无 ST」与「状态未记录」 |
| 行业快照可得时间 | 行内只有 `date`，没有 `as_of` / `available_at`；分区写入时间 19:09–23:59 不等 | 决策时点在盘中/盘前时，无法证明当日行业成分当时已可得 |
| 面板左端 | 3,060 只证券的首根 K 线就是 2018-01-08，且这 3,060 只在 `instruments` 里的上市日期**全部早于** 2018-01-08 | 说明是面板左截断而非 2018 年集中上市；但这仍不能给出 2018-01-08 之前的历史 |
| 北交所维表 | 面板中 355 只证券不在 `instruments`（样例全部为 `920xxx.BJ`） | 这些证券无本地上市元数据，生命周期无法核验 |

### 3.4 回测适用性判定（机器可读字段 `backtest_suitability`）

| 用途 | 判定 | 依据 |
|---|---|---|
| 日线截面回测 | **仅限探索性研究，不构成「数据可用」结论**（`supported: false`，`permitted_use: exploratory_research_only`，`integrity_checks_pass: true`） | 分区/行/日历/复权接口一致性全过，但那只是**本地一致性**；四项未知未解除：616 只无复权因子的证券、历史证券宇宙完整性、43,503 个缺口与 241 只提前停更的成因、成交可行性与流动性 |
| 含退市证券的全历史宇宙 | **不可用** | 无退市记录集，逐期证券宇宙无法证明完整 |
| 停牌感知的撮合/执行 | **不可用** | 无停牌表，且 `open==0 且 high==0` 的停牌形态行数为 0，本地无法识别哪些「证券×交易日」不可成交 |
| 历史行业轮动 | **不可用** | 时点行业只有 5 个交易日（0.23%），不足以支撑多年回测 |
| 复权价重建 | **可用（带未知）** | 因子契约与分区对齐通过；未知项为「无公司行为账时因子经济含义」 |

结论：在**书面声明下列限制**的前提下，这份数据**只够**支撑**探索性**的日线截面研究，样本区间 2018-01-08 → 2026-11-06（2,141 个交易日）。必须同时声明、不能省略的限制是：

1. 616 只面板证券完全没有复权因子行，其历史上的除权处理是否正确无法验证；
2. 逐股历史证券宇宙完整性未知，幸存者偏差无法排除；
3. 43,503 个「证券×交易日」缺口与 241 只提前停止更新的证券，成因未知——既不能当成停牌，也不能默认这些日子可正常交易；
4. 成交可行性未验证：换手率、涨跌停可交易性、容量都不在本次审计范围内。

它**不能**支撑退市/幸存者偏差校正、停牌感知执行，以及任何 2026-11 之前的历史行业收益验证。把本报告当作「数据可用」结论引用、或省略上述四条限制的用法，都不被本报告的证据支持。

本节在 2026-11-06 修正过一次：原表把日线截面回测记为「可用（带未知）」、机器可读字段为 `supported: true`，且未知项只列「逐股复权因子完整性」。该表述超出了本地证据能支持的范围（本地一致性通过 ≠ 数据可用），现改为上表口径，机器可读字段同步改为 `supported: false` + `permitted_use: exploratory_research_only` + 四项 `unknowns`。实测数值全部未变。

## 4. 机器可读报告结构

`coverage_report.json` 顶层字段：

- `schema_version`、`generated_at`、`audit_as_of`、`data_root`、`execution`（含 argv 与 `mode: read_only`）
- `inputs`：每个数据集的实测行数/分区数/区间
- `calendar`：日历来源与交易日数
- `checks[]`：11 项检查，每项 `id / title / required / status / evidence / findings / unknown_reason`
- `gaps[]`：所有非 `pass` 项的 `status` 与一句话原因
- `backtest_suitability`：上表五类用途。`daily_cross_section_backtest` 的 `supported` 含义是「能否支撑经验证的结论」，本次为 `false`；`permitted_use: exploratory_research_only` 才是许可范围，`unknowns[]` 是必须一并声明的限制，`integrity_checks_pass` 只表示本地一致性检查通过。消费方不得把 `integrity_checks_pass: true` 读成数据可用。
- `verdict`：`verdict / exit_code / required_failed / required_unknown / required_total`

`status` 只取 `pass / fail / unknown`；`fail` 一定伴随 `findings`，`unknown` 一定伴随 `unknown_reason`。消费方应按此 schema 判定，不要只读 `exit_code`。

## 5. 定向测试覆盖的失败模式

`test_audit_data_quality.py` 全部使用内存合成夹具，**不依赖真实数据、不写盘**，覆盖：

- 日历：缺失交易日、多出非交易日分区、无日历源时应为 unknown
- 面板：分区内重复行、行日期与分区不符、未来分区、非交易日分区
- 零价行：`open/high` 双零计入停牌形态、单侧零判为异常、未读价格列时判 unknown
- 复权：重复 / 冲突 / 越界 / 未来行；缺因子证券保持 unknown 而非静默通过
- ST：同股同日冲突；无记录日保持 unknown
- 维表：缺上市日期为 fail；面板证券缺席为 unknown；截断与「上市晚于面板起点」分开判（后者为确证矛盾）
- 行业：重复行、同股同日冲突、未来快照、非交易日快照、深度不足阻断回测
- 生命周期：逐股断更、内部缺口、左截断不误判为缺口、有停牌表时缺口升级为 fail
- 退出码优先级（fail > unknown > pass）与报告字段稳定性
