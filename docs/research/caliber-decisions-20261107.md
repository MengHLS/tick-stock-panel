## 1. 决定一：此前高/低点的权威口径

### 1.1 决定

**权威口径 = 「参照物不含当日，比较值 = 当日收盘」**，参照物的价基一律用**最高价 / 最低价**（复权），不用收盘价。

| 用途 | 权威定义 | 一句话 |
| --- | --- | --- |
| 突破型（上破） | `close > prior_high_N`，`prior_high_N = ts_delay(ts_max(high, N), 1)` | 今日收盘 > 此前 N 根 bar 的最高价 |
| 跌破型（下破） | `close < prior_low_N`，`prior_low_N = ts_delay(ts_min(low, N), 1)` | 今日收盘 < 此前 N 根 bar 的最低价 |
| 量能确认 | `volume > k × prior_vol_20`，`prior_vol_20 = ts_delay(ts_mean(volume, 20), 1)` | 今日量 > 此前 20 日均量 |
| 距离型（距高点） | `dist_prior_high_250 = close / prior_high_250 - 1` | 分母同样用 `prior_high_250` |
| 流动性门槛 | `prior_amount_20 = ts_delay(ts_mean(amount, 20), 1)` | 此前 20 日均额 |

**这条口径只有一条规则**：**参照物（分母 / 右端）永远不含当日；比较值（左端）永远是当日收盘**。突破型、跌破型、距离型、量能型全部同一条规则，不再有"含不含当日"的分歧空间。

### 1.2 依据（实测，n 与窗口见括号）

数据：2019-07-01 ~ 2026-10-30，3,384 只、5,470,011 ~ 5,510,001 行（`docs/factors/evidence/compare_stats.json`）。

| 对比 | corr | 平均绝对差 | 平均相对差 | 突破判定 jaccard | 仅研究侧成立 | 仅系统侧成立 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `prior_high55` vs `high_60d`（收盘 + 含当日 + 60） | 0.999642 | 0.4230 元 | 2.62% | **0.000** | 143,747 | **0** |
| `prior_high55` vs `prior_high60`（收盘 + shift1 + 60） | 0.999609 | 0.4361 元 | 2.67% | 0.504 | 3,893 | 130,975 |
| `prior_high55` vs `prior_high60`（**最高价** + shift1 + 60） | 0.999714 | **0.1301 元** | — | — | — | — |

读法（这三行就是决定 1 的全部论证）：

1. **含当日是决定性的**：换成"含当日"后 `both_true = 0` —— 5,470,011 行里一次都没同时成立。原因是结构性的，不是数据问题：当日收盘不可能高于"含当日收盘的最大值"。**S09 的入场条件用 `high_60d` 会恒不成立**。
2. **窗口不是真凶**：55 → 60 在最高价口径下平均只差 **0.130 元**，而价基从最高价换成收盘价要差 0.436 元、判定一致率掉到 0.504。
3. **平均绝对差完全看不出这场灾难**：0.423 元只占 2.62%，看起来"可接受"；但判定一致率是 **0**。所以**连续量的相关性/平均差不能当作阈值型因子的验收判据**——这条我升级为通用规则，见 §3.4。
4. **下破侧同理**：`close < low_60d` 触发率 **0.000%**，研究侧 `close < prior_low10` 触发率 **8.853%**。S02 的出场用 `low_60d` 等于永不出场。

### 1.3 `high_60d` / `low_60d` 怎么处置（保留、不改名、降级）

**决定：保留 id 与原语义，不加后缀、不改名；纠正显示名；在策略侧设为禁用。**

三个理由：

1. **同一个数，两种用法，对错相反。** `high_60d = close.rolling_max(60)` 含当日，对「近 60 日是否创新高」这类**状态判断是正确的**（今日收盘是 60 日最高，本来就是"创新高"的定义，`market_overview_builder.py:502` 的新高统计正是这么用的）；对「突破此前区间上沿」才是错的。错的是**用途**，不是这个数。给一个在展示侧正确使用的字段改名，等于为了防误用去破坏一个正确用法。
2. **改名的代价实打实**：`high_60d`/`low_60d` 被 7 处以上引用——`app/api/watchlist.py:368`、`app/strategy/monitor.py:57`、`app/strategy/custom_signals.py:61`、`app/strategy/scoring.py:156-159`、`app/strategy/ai_generator.py:65`、`app/services/market_overview_builder.py:444/502-503`、`app/factors/registry.py:166-171`（`distance_to_high_60d` 的 deps），外加前端字段名。收益（防误用）可以用一条评审门禁拿到，成本低一个数量级。
3. **误用的实际通道已经被堵住**：研究侧根本不需要 60 日窗口（用 20 / 55 / 250 / 10），S09 那条 55 日突破由 `prior_high_55` 取代。真正会误引用 `high_60d` 的场景是"随手找一个高点因子"，而这正是规格评审该拦的。

配套的强制动作（缺一条，这个决定就不成立）：

- **显示名必须改**：`pipeline.py:189` 现在写「60日最高价」，与实现（收盘价）不符，改为「60日最高收盘价（含当日）」；`low_60d` 同理。**这是文档缺陷，不是口径变更**，不影响任何计算。
- **台账语义字段必须加**：`semantics = incl_today_close`、`price_basis = close`、`shift = 0`。
- **策略规格禁用**：任何策略/信号配置把 `high_60d`/`low_60d` 写进入场或出场条件，评审**直接退回**，不讨论。
- **种子策略的 `shift(1)` 保留**：`app/strategy/seeds/breakout_new_high_60d.py:65` 在策略层做 `shift(high_60d,1)` 是对的，**不要删**——删掉会立刻变成"含当日突破"，即恒不成立。它是这个决定的临时实现，不是冗余。
- 可选加固（仅当架构师认为需要强隔离时）：在 registry 加只读别名 `high_60d_legacy`，**不动列名**。

## 7. 决定四（v1.2）：截面排名的掩码口径 E2

状态：**研究侧口径已决定，生效**。触发：2026-11-07 14:23，开发经理提交 E2「掩码截面排名」的实现与文字不一致，请研究侧判定。本节即研究侧的口径决策记录，与 §1–§3 同级效力。

**修订记录**：v1.1（14:30）为首版判定；**v1.2（14:40）** 把 §7.2 的「反算」升级为实测（§7.7），并修正两处措辞——①「研究实现更紧」改为「计数更低但集合不是子集关系」（见 §7.2 末段），②「应有 t×P」注明是均值量级（P 逐日 1,037–1,790 变动）。判定与影响面结论不变。

### 7.1 判定一：定性成立（附两处必须写准的修正）

**机制成立。** `pl.when(掩码).then(x.rank("average").over("date") / in_universe.sum().over("date"))`：`when/then` 只决定哪些行留值，**不改变 `rank()` 的作用域**。分子 = 当日**全样本**名次，分母 = **池内家数**。因此 `rk` 既不是 [0,1] 的分位、也不是可比的百分位，可以 >1；`rk <= t` 的真实含义是「全样本名次 ≤ t × 池内家数」。`research/strategy-search-20261107/scripts/common.py:190-201` 与 `docs/factors/FACTOR_GAP_SPEC_20261107.md` §3-E2 的口径定义（分母 = 掩码内非空样本数）确实对不上。**无反驳意见。**

两处修正（不影响结论，但照原话写进文档会被人反推错）：

1. **样本范围说「全样本（主板 60/00，当日非空约 3,095 只）」，不要说「全市场」。** `load_panel` 在 `common.py:98-101` 已把标的过滤为 `60`/`00` 开头，创业板、科创板、北交所从未进入排名样本。写「全市场」会让后来的人用 5,000 只去复算，永远对不上。
2. **空值不占名次，没有额外放大效应。** polars 1.44.1 实测（`backend/.venv`，5 个非空 + 3 个 null 的同一日期截面）：`rank("average")` 对 null 返回 null，且**不占用名次**，非空值名次连续为 1..5。所以偏差**只来自掩码作用域这一项**，不叠加「空值把名次整体顶高」。相应地，你举的「池内 2 只、全市场 6 个非空、池内最小 rk = 1.5」要成立，必须是池内最小值之前还有一个**非池内**值——6 个非空里全局最小者的 rk 一定是 0.5。机制对，这个例子写进文档会被下一个读者当成反例。

### 7.2 判定二：这不只是系统侧的错，研究侧也错，而且方向相反

**算术恒等式（这条可当场证伪，不用跑回测）**：若分母 = 池内非空家数 `P`，且名次也在池内计算，则 `rk <= t` 必然选中约 `t × P` 只（average 名次法下 ties 无影响，计数精确）。`P ≈ 1,430`（gap spec §3-E2 分母列）。名义 5% → 71.5 只，10% → 143 只，30% → 429 只。

实测选股数（gap spec §3-E2 表，调仓日平均）与名义值对比：

| 规则 | 名义 | 应有（t×P） | 研究实测 | 研究实际分位 | 系统实测 | 系统实际 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `rk_ret5 ≤ 0.05`（S06） | 5% | 71.5 | 49.7 | **3.5%** | 154.3 | 池内 10.8% |
| `rk_vol60 ≤ 0.10`（S07/S12） | 10% | 143 | 55.5 | **3.9%** | 307.2 | 池内 21.5% |
| `rk_ret20 ≤ 0.10`（S10） | 10% | 143 | 92.8 | **6.5%** | 308.8 | 池内 21.6% |
| S11 复合（两项 ≤0.30） | ≈9% | — | 14.7 | **1.03%** | 207.2 | 池内 14.5% |

四条全部系统性低于 `t×P`，没有一条例外。**结论：研究实现不是池内分位，系统实现也不是**（`rank(x)/count(x)`，分母 3,077–3,095，它更松，S07 选 307 只 ≈ 池内 21.5%）。两个都是错口径，方向相反，`E2` 原文「研究侧是对的、只需修系统侧」的框架不成立——`FACTOR_GAP_SPEC` §3-E2 的**口径定义**（第 184 行，分母 = 掩码内非空样本数）是对的，错的是把它读成「研究现状 = 基准」，以及第 173 行只点了系统侧。

可当场验伪的那一步（开发侧一条命令即可，不必跑回测）：**给出任一调仓日的 `P` 与 `count(rk_vol60 ≤ 0.10)` 两个整数。若比值不是 10%，就不是池内分位。** 我据此下的判定是 3.9%，所以不是。

### 7.3 判定三：权威口径（决定四）

1. **唯一策略可用口径 = 池内分位 `xs_rank_pool`**：`rank_average(x, over date, 限定 in_universe & x 非空) / count(x, 同一限定)`。值域 `(0, 1]`，当日最大值恒为 1。
2. **全样本分位 `xs_rank_market`**：仅作诊断，`strategy_usable = false`，策略规格不得引用。
3. **`xs_rank_pct`（= 现在的 `global_rank / pool_count`）**：保留 id 作历史与差异证明，登记 `semantics = global_rank_over_pool_count`、`strategy_usable = false`、`replaced_by = xs_rank_pool`。**任何策略结论不得引用它，也不得把它当"研究侧已复现"的证据。**

5. **硬校验（验收判据，缺一不通过）**：
