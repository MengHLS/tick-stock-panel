## 核心结论

1. WFO 已改为实际交易日窗口，拒绝 `full` 候选曲线进入账户汇总，并把低交易折保留为“经济结果有效、统计证据不足”，不再静默剔除。测试区间重叠也已修复。
2. 重跑完整 T74 基线仍精确得到 `+331.04%`；但该数字使用 73,853 条事后事件 allowlist、552 条历史 preClose 缺口修正和 1 条公司行为缺口修正，是“历史复现”，不是独立样本外策略收益。
3. 同一 T74 固定参数 WFO 改用单账户连续回放后，2025-01—2026-08 六个测试折的账户收益为 **+23.08%**（期末 123,080.95 / 初始 100,000），账户最大回撤 `-13.62%`，Sharpe 0.69、Sortino 0.98；旧口径逐折拼接只有 `+11.42%`，少算 11.66 个百分点。差异来自折边界：旧口径在每折末结算/重置，跨折持仓的后续盈亏不进任何一折。该结果仍受事后 allowlist 和参数/事件选择污染，不能视为可靠正收益。
4. 2023—2026 年三类固定动量/突破/择时候选、两个成本情景共 24 组仍全部亏损；没有新证据支持“可靠高收益”。
5. 历史日线包含 230 个在 2026-09 前停止更新的标的（主板 187 个），不是只用当前股票；但无外部证券主数据可证明退市宇宙完整。行业 point-in-time 数据目前仅 6 天，历史行业回填不能用于严谨策略结论。
6. 盘中监控新增逐标的行情年龄与复权降级守卫：陈旧、时间戳缺失/超前或复权因子不可用的标的被拒绝并给出机器可读原因，不再以“全市场最后日期相同”代替逐股新鲜度。
7. 项目已有复盘、盘中监控、市场阶段、模拟盘及研究扩展，问题在于证据和执行闭环仍有缺口；没有依据要求重写项目。

## 缺陷、口径差异与待验证项

### G12 / P1 / 已修复：滚动测试区间重叠

证据：`backend/app/backtest/walkforward.py` 的 `generate_folds` 原为 `test_end = test_start + timedelta(days=test_days)`，而回测起止均为闭区间。例如 2024-04-01 起 30 天，旧终点为 2024-05-01；下一折同样从 05-01 开始。

新增三个行为用例分别验证默认步长无重复日期、拒绝显式重叠步长、一天测试窗口只有一天。修改前 3 项全部失败，修改后所在定向集合通过。修复为 `test_days - 1`，并在 `step_days < test_days` 时显式拒绝；未调整训练端既有日期口径。

影响与兼容：新跑的 WFO 测试终点及折数可能变化；旧保存结果不被覆盖。调用方不应再以重叠测试区间作为可直接复利的账户结果。无前端字段、持久化 schema、缓存键变化。

### G13 / P1 / 已修复：WFO 汇总边界与低交易折

原实现 OOS 仍允许 `full`，而 `_calc_independent_candidate_result` 明确说明 full 曲线“不是账户净值”；`aggregate_oos` 却将其逐折 `total_return` 复利。交易数不足的折又被整折跳过，可能删除一段亏损期。

第二轮改动：

- API 在任务准入前拒绝 `mode=full`；`WalkForwardService` 再次 fail-closed，训练和测试均固定 `position`。
- 所有 OOS 成功折保留；交易数不足只写 `statistically_insufficient=true`、`trade_gate_ok=false`，不删除经济结果。汇总另给 `n_sufficient_trades`、`n_insufficient_trades`、`consistency_sufficient`。
- 返回 `return_kind=compounded_fold_returns_not_continuous_account`；前端文案改为“OOS 折收益拼接（诊断，非账户净值）”，并显示交易数不足折。

仍未解决、不能被这次修复掩盖：逐折账户重置、跨折未平仓、空档期与成本尚未通过唯一连续时间线 replay。`compounded_oos_return` 因此只能作诊断，不能作实盘账户收益。

### G14 / P2 / 已修复：自然日与交易日语义混用

第二轮将 `generate_folds` 增加实际交易日输入；服务从 `repository.list_enriched_dates` 解析日期，预览 API 使用同一数据源。训练/测试/步进步长均按交易日计数，区间不足 fail-closed，不再回退自然日。`WalkForwardConfig.trading_days` 仅用于离线复算和契约测试。

修复后的 T74 基线显示区间 2024-01-01—2026-10-12 只有 669 个可用 enriched 交易日，并非约 1,016 个自然日。旧版把 252/63 当自然日使用会显著缩短训练/测试覆盖，且不能与交易日参数解释混用。

### G15 / 部分验证，仍不足：历史宇宙和数据溯源

第二轮扫描 2018—2026 日线生命周期：

- 日线面板共 5,813 个标的，当前维表 5,536 个；355 个不在当前维表的标的全部是北交所 `920*` 代码，不属于本轮沪深主板候选。
- 230 个标的在 2026-09-01 前停止更新，其中主板 187 个、创业板 40 个、科创板 3 个；这些停止标的均仍在维表，名称包括 `退市大控`、`长生退`、`乐视退` 等。
- 因此本轮数据**并非只保留当前上市股票**，已包含退市/终止上市样本。没有外部交易所证券主数据、退市清单和停牌记录，仍不能证明历史宇宙完整，也不能证明供应商当时已公开这些行。

内容指纹记录本次输入，不能证明 point-in-time 可得性，也不能恢复被修订的原始数据。正式确认仍需补历史入池/退市/停牌、数据修订和公告时点账。

### G17 / 口径差异：`profit_factor` 不是现金盈利因子

当前核心统计中的同名值是平均盈利百分比 / 平均亏损百分比绝对值，项目中文一般称“盈亏比”。它与现金总盈利 / 现金总亏损不同，不能混读。此次结果另输出 `cash_profit_factor`，按实际平仓 `pnl_amount` 汇总，不重命名现有 API，也未改变优化器目标。若以后统一定义，需一并迁移展示、目标和历史结果版本。

### G18 / 已知限制：行业主线回填与盘中执行

`docs/market-phase.md` 已明确主线成员为当前快照回看历史，不能把当今行业/概念归属当作当年已知。故此次没有运行“行业强势历史回测”，也没有虚构行业超额收益。

`quote_service.py` 已有连续交易时段及快照日期守卫，所选测试通过；但仍未实测每个股票的盘中延迟、断流、通知送达与重启去重全过程。日期正确不等于报价足够新，日线或普通分钟不能证明开盘排队可成交。

### G19 / P1 / 已修复：逐标的行情陈旧与复权降级

原实现只用“enriched 快照日期 = 当日”判断可评估，`_evaluate_monitors` 对每一行没有独立的时间判据；停牌股、断流标的和盘中复权因子读取失败都会留下“日期是今天、价格是旧值”的行。`_flush_live_enriched` 在复权因子读取失败时只写 WARNING 并继续按不复权口径计算，历史指标与实时价格可能混用。

本轮新增 `backend/app/services/quote_freshness.py`：

- 逐行计算 `quote_age_ms`，输出 `quote_fresh` 与 `quote_stale_reason`；原因包括 `missing_quote_ts`、`invalid_quote_ts`、`future_quote_ts`、`stale_quote`、`adjustment_unavailable`。
- 默认最大行情年龄 120 秒（覆盖分钟级两轮轮询），超前容差 60 秒；缺失 `quote_ts` 列按 fail-closed 处理，不再用全市场日期兜底。
- 复权因子读取失败或文件缺失时，该资产类型本轮全部标的判为 `adjustment_unavailable`；盘中信号不注入。

接入点：

- `MonitorRuleEngine.evaluate` 在评估前过滤非新鲜行，并把拒绝数量/原因/样本存为 `latest_quote_rejections(asset_type)`；全部被拒时清空上一轮策略命中，避免页面继续显示旧结果。
- `QuoteService._evaluate_monitors` 对股票/ETF/指数三轮分别标注；板块轮、扩展观察器和模拟盘快照只使用新鲜行，`quote_freshness_status()` 暴露最近一轮报告。
- `_inject_intraday_signals` 在复权降级时直接不注入，并按 `quote_fresh` 过滤盘中信号。

这修的是“能不能用这一行价格产生可执行信号”，不证明数据源时钟、停牌恢复或通知送达。拒绝原因可见、可审计；被拒标的不再静默沿用旧价。

## 331% 基线的来源与可信边界

`.artifacts/331-parity-20261102/event_positions_rerun32.json` 由 `run_331_parity.py` 在 2026-11-03 生成，来源是外部原系统 T74 v4.0.0 的 closed-loop 存档 `id=6210042` 对拍。第二轮重新运行同脚本得到 `event_positions_rerun33.json`，核心结果逐项一致：

| 项目 | 实际值 |
| --- | ---: |
| 区间 | 2019-01-02—2026-10-12 |
| 初始资金 / 期末权益 | 100,000 / 431,040.45 |
| 累计收益 | +331.04% |
| 最大回撤 / Sharpe / Sortino | -39.65% / 0.86 / 1.29 |
| 交易 / 已完成 / 期末未平仓 | 1,352 / 1,347 / 5 |
| 现金盈利因子 | 1.2642 |
| 已平仓收益 ≥20% 的交易 | 50 |
| 蒙特卡洛回撤 p95 | -98.94% |

该数字不能直接视为“可靠高收益策略”的原因：

- 不是独立样本外。整个 2019—2026 区间同时用于事件选择和结果观察；WFO 测试区间直到 2025 年才开始。
- 不是系统从全市场自然产生候选。参数携带 **73,853** 条 `_event_allowlist`，事件来自外部 SQLite 的事后事件集；策略只在这些事件内寻找入场。
- 使用 **552** 条 `_legacy_preclose_gaps` 修正和 1 条公司行为缺口修正，目标是与原系统对拍，不是从当前标准数据独立复原。
- 期末 431,040.45 元中有 430,435 元是 5 个未平仓头寸的盯市市值，现金仅 605.45 元，暴露 99.86%；没有证明这些持仓能在期末按市价成交。
- 成本为佣金 2.5 bp、卖出税费 5 bp、滑点 5 bp，未覆盖冲击成本、集合竞价队列和容量；最大 5 仓、满暴露，蒙特卡洛回撤 p95 接近 -99%。
- 核心 `profit_factor=2.07` 是平均盈亏百分比之比；按实际现金流计算为 1.2642，不能混读。

因此“331%”可验证的是**历史复现一致性**，不是可交易性、独立样本外收益或未来收益承诺。

## 第三轮：连续账户 WFO（已实现）

上一轮把 `compounded_oos_return` 改名为诊断值，但没有解决折边界结算问题。本轮让撮合器真正跨折结转账户，而不是改字段名。

实现方式（`backend/app/backtest/engine.py`、`strategy.py`、`walkforward.py`）：

- `PortfolioCarryState` 以 **symbol** 为键结转现金、峰值、持仓、次日开盘买计划、最后有效收盘价；每段矩阵的列号重新映射，不允许用上一段的 `asset_id` 指本段。
- `SimulationOptions.carry_in/carry_out`：段末不清算、不落 `end` 成交；段末原始买点转成跨段开盘计划，段末已触发的卖点转成次日开盘挂单，避免折边界吞掉一天信号。
- 折边界只切换该折 OOS 参数；已持仓继续按新折的风险/持有规则管理。空仓空信号折产出平线权益并继续结转，不报“无买入信号”。
- 结转持仓在下一段矩阵缺失时 `ValueError` 中止，不静默丢弃持仓；任一段 OOS 失败也立即停止回放，不拿失真状态拼后续折。
- API 新增 `continuous_account`（默认 `true`），并进入 job key；前端展示“连续账户收益”，逐折拼接降为诊断行。

### 期末头寸核对（报告错误，已修正）

上一版表格把末折“折末持仓”写成 0，同时汇总保留 5 笔未平仓，两者矛盾。只读核对 `wfo-t74-continuous.json` 后确认这是**报告错误，不是代码记账错误**：

- 前 5 折 `open_at_end_count` 均为 0，只有末折为 5；中间折的持仓通过 `carry_state` 结转，没有被记成独立 `open_at_end` 交易。
- 末折 `carry_out=False`，不产出 `carry_state`，旧字段 `carried_out_positions` 因此恒为 0；真实的期末持仓在权益曲线末点 `positions=5`。表格误把“无结转状态”当成“无持仓”。
- 交易生命周期自洽：各折 `n_trades` 相加 `36+37+45+42+41+49 = 250`，等于账户 `n_trades=250`；`completed 245 + open_at_end 5 = 250`；250 条交易键（代码+入场日+出场日+入场金额）无重复。

- `research/.../verify_continuous_account.py`：新增 8 项独立核对（现金+市值=权益、期末持仓=未平仓交易数、末边界=期末持仓、交易数相加、未平仓只来自末折、无重复交易、引擎不变量全真）。

修复只改报告字段与校验，不改变撮合、成交或收益计算；重跑后累计收益、回撤与逐折权益应与上表一致。

同一批参数下逐折重置口径仍为 `+11.42%`、4/6 折为正、IS→OOS 退化 1.5617。两种口径的折收益逐项不同（例如第 1 折 +0.98% vs +7.08%），说明旧口径不是“保守估计”，而是把折边界持仓的后续盈亏删掉了。报告保留两者，但只有连续账户值可以称为账户收益。

## 行业 point-in-time 与历史宇宙

本地 `ext_hy_ths_pit` 行业快照只有 2026-11-01—11-06 共 6 个日期分区（含周末，不能等同于 6 个交易日）；`ext_gn_ths` / `ext_hy_ths` 为当前快照而非历史时间序列。任何 2023—2026 行业强势回测若直接使用当前成分，都会把后来归属带回过去。本轮因此没有生产“历史行业强势正收益”，只保留方案；至少要有覆盖训练/测试窗口的逐日或月度历史成员快照，才能进行行业方向验证。

历史宇宙扫描发现 230 个停止更新标的（主板 187 个），说明源数据保留退市样本；但缺少交易所退市清单、停牌全表和供应商修订记录，仍不能宣称无幸存者偏差或 point-in-time 完整。

## 固定候选与检验协议

本轮第一次运行前固定三类简单规则，不按结果调整阈值：

- 共用宇宙：历史面板中的沪深主板 `60*` / `00*`，历史 ST 明确为正常，至少 120 根已观察日线，原始收盘价至少 3 元，前 20 根日线平均成交额至少 1 亿元。
- 动量：60 根日线涨幅截面排名前 10%，收盘高于 MA60，且 MA20 高于 MA60；按 60 日动量降序排序。
- 突破量能：动量条件上，加收盘突破**此前**55 根日线最高价、当日成交量超过**此前**20 根日线均量的 1.5 倍。
- 突破量能加择时：再要求当日可计算 MA60 的主板样本中，收盘在 MA60 上方的比例至少 50%。这是收盘已知、次日交易的宽度门控，不调用带回填行业的主线标签。
- 共用退出：收盘跌破 MA20 后下一交易日开盘，或最大持有 20 个实际会话；本轮没有盘中止损、固定止盈或借事后最高价退出。

每年单独启动 100 万元账户、最多 5 仓、入场目标总暴露 60%；价格上涨后暴露允许漂移，并非每天硬再平衡到 60%。四个正式区间分别为 2023、2024、2025 全年可用日期及 2026 年至 10 月 30 日；每折额外读取 400 个自然日作预热，指标按每个标的历史行计算。停牌跨期与不规则缺行的窗口影响仍需专项核查。

实际样本边界如下；面板标的数包含预热期，撮合矩阵标的数也不等于每天满足全部入场条件的标的数。三规则、两成本情景共用各年度输入面板，不按结果更换股票宇宙。
