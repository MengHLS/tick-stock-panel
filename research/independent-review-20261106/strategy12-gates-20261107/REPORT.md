## 1. 判定口径复核（E1 的 2% 与 E2 的全部字段）

### 1.1 E1 原本想测什么

`E1_E2_SPEC.md:77` 的 FAIL 条款原文：

```
| **FAIL** | |cagr_pp| ≥ 3.0，或 A 组 `open_at_end_share` > 2%（基准收益依赖"最后价挂账"） |
```

括号里的理由是这条门槛的**全部立法意图**：当回测在期末还持有"已经没有最新报价"的股票时，权益曲线用的是最后一根 bar 的价格（last price carry），此时"全期年化"可能建立在一个不可变现的估值上。E1 想测的是：**基准收益里有多少比例依赖陈旧报价**。

### 1.2 实际测到了什么（分子 / 分母）

| 环节 | 代码位置 | 实际口径 |
| --- | --- | --- |
| 分子 | `scripts/e1_survivorship.py:124` | `mv = sum(x['market_value'] for x in result['final_positions'])` —— **全部**期末未平仓持仓，不区分是否有当日报价 |
| 分母 | `scripts/e1_survivorship.py:127` | `open_at_end_share = mv / values[-1]`，期末权益 |
| 判定 | `scripts/e1_survivorship.py:22` | `if abs(diff_pp) >= 3 or share_a > .02: return 'FAIL', 3` |
| 传入 | `scripts/e1_survivorship.py:146` | `judge(..., groups['A']['open_at_end_share'], ...)` |

即：分子是"是否持仓"，立法意图要的是"是否用陈旧价挂账"。两者在本样本上**恰好相反**。

### 1.3 本样本的实测分离

`results/e1_v3/e1_survivorship.json` 与 `run_C00_A.json`：

### 1.4 两份"不能做"的清单（纪律条款）

1. **不得改分子追 PASS。** `E1_E2_SPEC.md:192`（A.4）已经写死"这里 A 的 2% 依旧按原文全部未平仓持仓计算，不偷换为仅停更持仓"。v3 的执行忠于冻结规则，改造分子后把 v3 改判 PASS 属于事后改判，破坏预注册。v3 的 `FAIL / exit_code 3` **原样有效**。
2. **不得据此宣称"严重幸存者偏差"。** 独立重算（不依赖报告结论）：`diff.cagr_pp = (A.cagr − B.cagr)×100 = (+0.0806619)pp`，逐年最大 |diff| = 0.5100pp（2022 年），最小 −0.1799pp（2024 年）。A 与 B 都在 −13.1%/−13.2% 一线。方向为 A > B，即**保留停更股反而略高**；这与"只保留存续股会抬高收益"的幸存者偏差方向相反，且量级 0.08pp 不足以支撑任何"严重"表述。

**正确的表述只有一句**：本 C00 基准对停更样本不敏感（0.08pp），但 C00 是 5 只高流动性等权组合，不能外推到其他策略；E1 v3 的 FAIL 是规则缺陷造成的，不是数据缺陷造成的。

**(a) DATA_MISMATCH 是恒等式，等于死代码。**

## 2. "复现 vs 新试验"边界规则

### 2.1 判定的对象不是"策略名字"，而是一次执行的身份

一次执行的身份由 5 元组决定：

```
(H 假设定义, P 参数集, E 执行口径, D 数据快照, W 评估窗)
```

`D` 必须有哈希（面板 `fda82b47…`、`panel_ipc_sha256`），`E` 必须绑定引擎与矩阵代码哈希（`engine.py`、`matrix.py`），否则"复现"不可证。**当前 12 条 run 的产物里没有记录引擎哈希**——这是既成缺陷，`obs-fix-20261107/PROTOCOL_OBSFIX_v1.md` §2 已经自己指出（旧 S07 产物 23:19:26 早于 `engine.py` 的 00:01:33，无法证明同引擎）。因此**从现在起，任何新 run 必须把 `engine.py`/`matrix.py` 的 sha256 写进产物**，否则不满足复现的举证条件。

本轮审核所依据的代码指纹（自算，见 `checks.json:sources.sha256`）：`engine.py = ecc3d826…`、`matrix.py = fd4938c9…`、`e1_survivorship.py = 1c6f85ef…`、`judge_e2.py = 2846abf5…`。其中 `engine.py` 与 `obs-fix-20261107/results/verification.json` 的 `V1.observed.engine_py` **一致**，说明自 01:28 冻结以来引擎未变；但这仍不能把 11-06 23:19 的 12 条 run 追认为同引擎。

### 2.2 分类规则（可机器校验）

| 情形 | ΔN | 判据 |
| --- | --- | --- |
| H、P、E、D、W 全同，且 **逐笔等价**（权益序列、trades 的 symbol/entry_date/entry_price/exit_date/exit_price/shares 全同） | **0** | 复现。允许的差异只有机器、耗时、输出路径、以及"只改写出什么不改算出什么"的持久化补全 |
| P 任一变化（阈值、分位、窗口长度、max_hold、排序键、宇宙门槛） | **+1 / 每个不同 P** | 不是每个折、不是每个成本情景各 +1；是一个参数点 +1 |
| E 任一变化（成交时点、涨跌停/停牌处理、手数、费用、滑点、最大仓位数、`block_limit_open`、`finalize_open_at_end`） | **+1**（若结果改变且改动由已见结果触发） | 见 2.3 的"结果触发测试" |
| D 变更（供应商修订、复权基准变化、补数据） | 重算全部；若任一结论改变 → **+1**；旧结果必须保留 | 不得两条并存择一报告 |
| W 变更（延长数据、移动 OOS 边界、换 T2 起点） | **+1** | 每次窗口变更 |
| 只读诊断（E1、PATH_RISK、OBSFIX count/full、本文件） | **0** | 前提：**不得用于选择候选**。一旦某诊断结果影响了"报哪条"，按择优 +1 |
| 同一假设的不同成本情景（10/30/gross） | 主情景 0；**被报告为可选结果的附加情景 +1** | 只报 10bp 且不比较 → 0；把 30bp 拿出来当结论 → +1 |

### 2.3 灰区："为了让策略能跑而改执行假设"

这是研究方最可能踩的线，也是最难判的。例子（都真实存在于本批）：

1. 信号次日开盘涨停 → 丢弃 vs 顺延 vs 按涨停价成交。规格 `STRATEGIES.md` 只写"收盘决策、次日开盘成交"，没写被拦怎么办。三种选择的结果差异是**数量级**的：S02 的涨停拦截 4,004 次 vs 实际成交 442 笔。
2. 停牌导致的次日无 bar → 顺延到复牌（当前实现）vs 作废（真实日单）。
3. 期末未平仓 → 按最后价落账（`finalize_open_at_end=True`）vs 不计入权益。

**可执行判据（结果触发测试）**：

> 一个改动若**在看到本批任何结果之后**做出，且改后结果与改前**逐笔不等**，则 ΔN = +1，无论它叫"修 bug""统一口径"还是"补持久化"。
> 只有在**任何结果产生之前**就已经确定、且有独立记录（测试、规范、第三方审核）的改动，才能 ΔN = 0。

理由：抬高 DSR 门槛要防的不是"想法多"，而是"抽签次数多"。改执行假设会得到一条**新的、不同的**权益曲线，研究者据此决定报不报——这就是一次抽签。

**推论（必须写进下一版协议）**：执行缺口的默认值必须在**开跑前一次性写定**，对 12 条策略和 C00 对照组**同一条**，并声明"这是最保守/最接近真实的哪一个，理由是什么"。任何按策略分别选择的口径，每一条都要 +1。

### 2.4 N 的表述规则

**任何 DSR 输出必须同时声明 5 项**，缺一项即不可引用：

1. N 的数值；
2. N 的来源（账本 / 本轮枚举 / 家族聚类）；
3. `V[SR]` 的估计方式（用哪几次试验的 Sharpe）；
4. 是否包含未登记的历史探索（本项目：包含不了，故 N 只能是下限）；
5. 结论对 N 的敏感性（至少给 N=15 / 17 / 30 三档 SR0）。

**当前状态**：`GLOBAL_LEDGER_v3.json` → `global_N_exact = null`，`global_N_lower_bound = 15`；同一文件 `reconciliation` 段自认"与 prior3 的参数/方向/选择重复性未逐项验证"。本轮独立枚举维持 **17**（12 + T03 的 3 条 + 2 条互不相同的首板规则），理由与逐条去重见 `research/independent-review-20261106/e1-ledger-20261107/HYPOTHESES.md`。

**因此 `PROTOCOL.md:174` 的写法"N=15（起）"已经过期**，应在下一版改为：

```
DSR ≥ 0.95，N 取 §6 的累计值；当前 N_exact = unknown，下限 17。
任何 DSR 必须同时报告 N=17/30/60 的 SR0 与 DSR，且以较大 N 的结果为准。
```

否则会出现"用已知最小的 N 去过门槛"——这正是最容易被绕过的地方。

### 2.5 一条最容易被绕过的漏洞：「实现修正」豁免

**漏洞形态**：把一次会改变成交的改动，叙述成"这不是新试验，只是把实现改对了"，从而 ΔN=0，白拿一次抽签。

本项目已经有**正例**：`obs-fix-20261107` 声称"改的是写出什么，不是算出什么"，并用 V3（count vs full 逐笔相同）+ V4（与旧 run 的 314 笔、1779 个权益点相同）机器证明 → 这个 ΔN=0 是**成立的**，因为它满足了逐笔等价。

**同一话术可以套在反例上**：本文 §3 证明 `matrix.py:3194-3207` 的信号延迟是"按该证券自己的下一根有 bar"，不是"下一交易日"；若把它修正为"下一交易日、无 bar 则作废"，S03 的 4 笔跨停牌成交会消失（占其总盈亏 22.02%）、S01/S04/S05/S06/S10 共 11 笔同理。修正后权益曲线不同、交易列表不同，但只要一句"这是 bug 修复"，就能主张 ΔN=0。

**封堵**：复现的判据**不是叙事，而是逐笔等价（trade-list hash + equity hash）**。任何使 ≥1 笔的 `entry_date/entry_price/exit_date/exit_price/shares` 改变的改动，一律 +1；唯一豁免是"先于结果发现、由独立方记录、且改动前后差异被完整披露"的修正，并且它只能**替换**旧结果，不能**新增**一次抽签（旧结果仍留在账本里，不得两条并存择一报告）。

### 3.2 未建模 / 失效的 3 处（按影响排序）

#### (a) P2：「次日开盘」实际是「该证券下一根有 bar」，不是下一交易日

`matrix.py:3194-3207`：

```python
rows = np.flatnonzero(present[:, asset_id])      # 该证券"有 bar"的行
source_rows = rows[: len(rows) - delay_bars]     # 信号
target_rows = rows[delay_bars:]                  # 成交：下一根"有 bar"
output[targets, asset_id] = 1
```

后果：**信号之后若停牌，成交被顺延到复牌第一根，按复牌开盘价成交**；真实世界里"次日开盘"的日单会当天失效。

实测（从 `run_*_10.json` 的 `entry_signal_date` 与权益日历反查）：

| 策略 | 迟到成交 | 例 |
| --- | --- | --- |
| S05 | 3 | `000933.SZ` 2022-04-25 信号 → **2022-05-13** 成交（13 个交易日停牌） |
| S03 | 4 | `600576.SH` 2021-04-30 → **2021-05-20** |
| S06 | 4 | `002564.SZ` 2023-04-28 → **2023-06-30** |
| S04 | 2 | `002500.SZ` 2020-06-16 → **2020-06-29** |
| S01 / S10 | 1 / 1 | — |
| **合计** | **15 / 5,517（0.27%）** | 最长迟到 13 个交易日 |

**金额影响不能忽略**：这 15 笔的盈亏占其策略总盈亏的比例为 S03 **22.02%**、S10 **15.65%**、S06 **14.45%**、S01 **12.53%**、S04 −2.79%、S05 −3.05%。本批方向多为负（虚构成交在拖累收益），但**它是虚构成交，不是保守偏差**——修正后结果会变，且变动量足够改变一条策略的"失效/不失效"判断。

同时：`buy_suspended = 0`（12 条全部为零）就是这个延迟方式的直接指纹——若延迟按交易日算，停牌次日必然产生 `buy_suspended`。

#### (b) P2：复牌首日的涨跌停闸门被 `NaN` 前收盘静默关闭

`engine.py:2943-2951`：

```python
previous_close = float(matrix.raw_pre_close[time_id, asset_id]) ...
if _valid_price(previous_close) and ... :
    limit_up = ...
    if open_price >= limit_up - 0.005: return False, "buy_limit_up"
```

`matrix.raw_pre_close[t]` 取自矩阵第 t−1 **行**。复牌首日的第 t−1 行没有该证券的 bar → `NaN` → `_valid_price` 为假 → **整个开盘涨停门控被跳过**。

复现（本轮实测，只读探针）：对 2021-04-20..2021-05-21 的切片重建矩阵，`600576.SH` 在 `2021-05-20` 行：

```
open=7.0  raw_open=7.0  raw_pre_close=nan  price_limit_pct=0.1  tradable=True  up_locked=False
```

上一根 bar 是 2021-04-30 收 6.36，涨停价 = 7.00，开盘 7.00 → 应拦未拦。成交记录里 S03 的这笔正是 `entry_price = 7.007`（= 7.00 + 10bp 滑点），当日收 5.76。

`_limit_down_price_at`（`engine.py:2959-2989`）用同一个 `raw_pre_close`，**卖出侧对称失效**：复牌首日跌停开盘的卖出不会被拦。本轮 15 笔迟到成交里命中涨停开盘的 1 笔（1/15），量级小，但缺陷类别是"最需要闸门的那一天闸门恰好关闭"。

#### (c) P2：无成交量/参与率约束，滑点与金额无关

`engine.py` 买入路径中没有任何 `volume`/ADV/参与率判断（全文 `participation|adv|volume_limit` 零命中），`ExecutionCostPolicy.buy_slippage_tiers` 存在但 `common.py:328-331` 未传 → 滑点恒为 10bp，与下单金额无关。

对当前规模**不material**：100 万账户、最多 60% 仓位、5 仓 → 单笔约 12 万元；宇宙门槛 `prior_amount20 ≥ 1e8`（`common.py:67`）→ 单笔约占 ADV 0.12%。但账户到 1000 万、或策略集中在"刚好 1 亿成交额"的边缘标的时，该假设失效。

### 3.3 哪几类策略会因这些缺口而收益虚高

判据不是"缺口存在"，而是"缺口方向对这个策略族有利"。

| 族 / 策略 | 主要暴露 | 方向 | 说明 |
| --- | --- | --- | --- |
| **截面反转** S06、S10 | ①停更/退市挂账（持有的是最弱 5–10%，最可能一路跌到消失）②高换手（15.4×、5.3×）叠加 10bp 固定滑点 ③无 ADV 约束 | **虚高** | 这类策略买"跌得最狠的"，而面板无法区分退市/长期停牌（无生命周期表），持仓停更时按最后收盘价挂账 → 亏损被封顶。同时其标的是宇宙内流动性最差的一档，10bp 是乐观值。**这是最需要打折的一族** |
| **均值回归** S04、S05 | ①同样的停更挂账 ②复牌首日成交（本轮 5 笔虚构成交里 2 笔落在这一族） | **混合，偏虚高** | 停更挂账方向虚高；但本轮虚构成交多为亏损，方向上反而拖累。两股力量未分离，标 UNKNOWN |
| **趋势突破 / 动量** S01、S02、S08、S09 | ①涨停开盘不可买（拦截 189/4,004/253/1,387 次）②复牌首日成交 | **偏低估，不是虚高** | 被拦的信号直接丢弃、不重试 → 最强的突破日拿不到货，收益被**低估**。真正虚高的只有"复牌首日按涨停价成交"那 1 类。**结论要说清楚：这一族的风险是"结果不可实现"，不是"结果被美化"** |
| **截面因子 / 低波** S07、S11、S12 | ①期末持仓按最后价挂账（S07 期末暴露 59.31%）②停更挂账 | **轻度虚高** | 低波标的本身流动性好、退市概率低，是四族里受影响最小的；但 S07 是唯一 T2 Sharpe 接近门槛的（0.967），其 59% 期末暴露与陈旧估值需要在报告里点明 |

**必须先说的一句话**：这些缺口**不可能把本批任何一条救活**。原因是量级——最好的全期 Sharpe 是 0.031，门槛 0.50，DSR 零假设线 0.80–0.83；撮合缺口带来的偏差是"每年几个百分点"级别，不是"Sharpe 0.8"级别。**工程通过不等于盈利通过，盈利失败也不靠"撮合没做好"来解释。**

## 4. 未知与未验证（不得用于结论）

1. **停更 ≠ 停牌 ≠ 退市**。无权威生命周期表（`security_lifecycle_coverage = unknown`）；`S_stale` 只是"最后 bar 早于阈值"的近似。任何"因停牌/退市造成 X"的表述都不成立。
2. **839 日对账不平的原因未证明**。PATH_RISK 记录的 839 个异常日、最大绝对差 68,544 元，成因（复权、股本、分红现金流）**均未证明**，不得归因。
3. **OBSFIX V5 的 13 天 / 最大 6.23% 权益差未解释**：`obs-fix-20261107/results/verification.json` → `V5.days_over_1cny = 13`，最差为 2022-08-11 的 49,416 元（占权益 6.231%），文件自标 UNKNOWN。这 13 天里权益曲线与交易流水**不自洽**，任何以逐日估值做的路径结论在这 13 天不可靠。
4. **1,839 个不可归属持仓日**仍在（`path_risk.json`），本轮没有新的生命周期数据，状态不变。
5. **撮合真实性的盘中部分**（排队、部分成交、集合竞价可得性）日线数据无法验证；本文件只判定"哪些被建模、哪些没有"，不判定"现实里能不能成交"。
6. 未验证：`matrix_native` 共享矩阵路径、真实多年 WFO、全后端 `pytest tests`、前端构建与联调。
