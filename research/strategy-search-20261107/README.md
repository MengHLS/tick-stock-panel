**新增独立复算（E2 判定器附带，12/12 条一致）**：

- 从 `run_*.json` 的权益曲线重算 Sharpe，与 `registry.json` 的 ALL/T2 Sharpe **12 条全部逐位一致**；

这两项说明"登记表数字与交易明细出自同一套计算"，不是手填的。

**新增发现（本轮只读检查）：`segments[].stats` 不能用于年度归因**

- 36 个 run × 8 个自然年 = 288 个 segment-year，用**连续权益曲线**重算年收益后，**219 个（76%）与 `segments[].stats.total_return` 差异 > 2pp**。
- 典型例（`run_S07_xs_lowvol_60d_10.json`）：2024 年曲线重算 **+33.6%**，`segments.stats` 写的是 **−4.04%**；2023 年曲线 −4.76%，字段 −28.2%。
- 原因推测：`segments[].stats` 是折内引擎统计，不带 carry 结转口径；与 `equity` 曲线不可互相校验。
- **规则**：年度归因、单年集中度、回撤归因一律从 `equity[]` 重算（`REPORT.md` 的年度表就是这么来的，数字与曲线一致）；`segments` 字段只能当折内参考，不得直接引用。
