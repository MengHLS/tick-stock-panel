## ① 规格：唯一改动 = 出场

### 1.1 主假设（固定，不搜索、不并列）

**移动止损（peak-based trailing stop），宽度 0.25（=25%），peak 口径 = 收盘（close），无激活门槛。**

唯一允许的另一种写法是它的等价直述：出场线 = `max_close(截至前一交易日) × 0.75`。

**族归属（R4b）**：这不是「新机制假设」，而是既有 **trailing-drawdown 机制族**内的一次性参数位置检验——引擎里 arm2 的移动止盈与它**同一条线**（`_trailing_risk_line` `engine.py:3012-3023`，线 = `peak × (1−|d|)`；两个调用点 `:3077-3089` 与 `:3090-3103`/`:4040-4053`），差别只在 d = 8% → 25%、并去掉 +10% 激活门槛。按 F1 一次性例外登记，跑完即关族（关族条件见 §④.1）。

**先验理由（只许这样写，不得引用 199 笔的回吐分布）**：

1. 主板日跌幅上限 10%、创业板/科创板 20%，**25% > 2× 主板跌停**（0.25 > 2×0.10）；单个跌停日 + 次日惯性不足以触线，所以该止损不会退化成「日内噪声止损」——这一点与本池已被证伪的 −8% 档（触及率 81.9%）在结构上不同。
2. 移动止损**不封顶上行**：它只抬高下线，不设目标价，不改变盈利单的持有上限，因此结构上不破坏 S01b 已证实的「收益来自少数长持右尾」。

**明确不做**：不调 0.25（不试 0.20/0.30），不加激活门槛，不改 peak 口径，不并列任何第二名。

## ② 预注册判据（写在本轮任何 run 之前；只给不等式）

记号：`T`=总收益（期末权益/1,000,000 − 1）；`A`=全期年化 = `(1+T)^(252/N_td) − 1`，`N_td`=该 run 的交易日数；`MDD`=日权益曲线（收盘盯市，含未平仓）的最大回撤 = `min_t(equity_t / max_{s≤t} equity_s − 1)`；`OOS_A`=用**同一条**日权益曲线切 `2023-01-03…2026-10-30` 子区间后按**已落盘口径**（`metrics.json#a0_10bp.oos_by_scen.*.oos_annual`，其 `oos_years=3.833`、`oos_days=925`）年化——**不是第二次回测**。

基准读数（10bp / 30bp）：`T₀=+24.27% / +13.43%`；`A₀=+3.13% / +1.80%`；`MDD₀=−39.27% / −40.89%`；`OOS_A₀=+4.73% / +3.32%`。

口径自检（写死为前置）：① `A` 的函数必须能把基准 `T=+24.27%` 复现成 `+3.13%`，反解 `1.2427^(252/N_td) − 1 = 0.0313` ⇒ `N_td ≈ 1,777`；② `OOS_A` 的函数必须能把基准 `1,040,990.10 → 1,242,725.28` 复现成 `+4.73%`（30bp：`1,000,646.57 → 1,134,266.20 → +3.32%`）。**任一条复现不出，先报口径差异并停，不得用近似口径往下判。**

### P1 收益不劣化（10bp 档）

- `T ≥ +24.27%`
- 且 `A ≥ +3.13%`（交易日/252）
- 且 `N_td` 与该臂基准 run 相同（`≈1,777`）；**不同则本 run 无效**（区间/日历不一致），不得用于判定。

### P2 回吐改善（10bp 档）

- `MDD ≤ −36.27%`（比基准 −39.27% **至少改善 3.00pp**）。

**PASS 的第一层 = P1 ∧ P2。** 单独满足 P2、不满足 P1 ⇒ 不是 PASS。

### P3 右尾（两条臂同一口径，各算一次；R1/R2 已改）

**去尾口径**：对每条臂**各自**的成交表，按 `pnl_amount` 降序分别去掉最大 1 笔、最大 5 笔，重算总收益

`T_k = (期末权益 − Σ_{i∈top-k} pnl_i) / 1,000,000 − 1`（k = 1, 5）

其中 `pnl_i` 对 `exit_reason != "end"` 取 `pnl_amount`，对 `exit_reason == "end"` 取 `(exit_value − entry_value)`（引擎把后者写成 0，见 §⓪ R1）。两条臂同一规则。

**① 前置对账（必做，先于任何比较）**

`|Σ_all pnl_amount + Σ_{end}(exit_value − entry_value) − (期末权益 − 初始资金)| ≤ 0.01 × 笔数`

并逐行列出全部 `end` 笔（symbol / entry_date / exit_date / entry_value / exit_value / 差额）。

不成立 ⇒ **本次 run 无效（数据完整性前置）**：不判定、不占判定、不记灰区、不进结论、**不占 N**；修数重跑后同一预注册内的这次无效 run 不计入 N。**不得写成策略 FAIL。**

基准必须复现（我实测，见 §⓪ R1 表）：`326,858.21 + (−84,132.95) = 242,725.26`，对 `242,725.28` 残差 `−0.02`，容差 `1.99` ⇒ 通过。

**② 门（只此一条）**

`D_k = T_k(被测) − T_k(基准)` 在 `k ∈ {0, 1, 5}` 三个点上**符号一致**（`D_0` = 全期总收益差）。符号一致 = 三个 `D_k` 同号或同为零；任一异号 ⇒ P3 不成立。

**③ 报告项（逐值列出，不作门）**

被测臂 `T_1`、`T_5`、top-1/top-5 明细（symbol / 区间 / `exit_reason` / pnl），基准同项逐值列出。基准本身 `T_1 = −9.92%`、`T_5 = −75.72%`，其绝对值与门无关（R2：v1 的「去尾后 `T_1>0` 且 `T_5>0`」已作废，结果它基准自身就过不了）。

- **禁止只对被测臂去尾**；两条臂的 top-k 是各自的前 k 笔，不取交集、不按同一批标的对齐。
- `D_k` 的绝对值只报告、不设阈值：本轮对「右尾依赖程度」不下任何量的判语，只判「改进的方向是否只在去尾后才出现」。

### P4 成本（两档结论一致）

- 30bp 档判据同构，基准换成 30bp 读数：`T ≥ +13.43%` 且 `A ≥ +1.80%`；`MDD ≤ −37.89%`（−40.89% + 3.00pp）。
- 10bp 与 30bp **两档都必须 PASS 各自的第一层（P1∧P2）**。两档结论不一致（一 PASS 一 FAIL）⇒ **整体按 FAIL 记**，不得取「更好看的那档」。

### P5 样本外

- `D_OOS = OOS_A(被测) − OOS_A(基准)` 与 `D_0 = T(被测) − T(基准)` **符号相同**；两者均用各自成本档内的同一函数计算。

### 判定与灰区（完整、无遗漏）

| 结论 | 条件 |
|---|---|
| **PASS** | P1 ∧ P2 ∧ P3 ∧ P4 ∧ P5 全部成立 |
| **FAIL** | 命中任一：① 三个收益维同时劣化（`T < T₀` 且 `A < A₀` 且 `MDD > MDD₀`）；② P3 的 `D_k` 在 `k∈{0,1,5}` 上**符号不一致**（R2：原「`T_1≤0` 或 `T_5≤0`」已删除）；③ 两档 PASS/FAIL 不一致 |
| **不确定·不采用（灰区）** | 以上都不命中（其余一切情形，含「只差 0.1pp」「MDD 改善 2.9pp」） |
| **无效 run（不占判定、不进灰区、不占 N）** | ① P3 去尾对账不成立；② `N_td` 与基准不同；③ 基准臂未复现§1.6 的锚点 |

- R1 后：对账不成立**不再是策略结论**，而是数据完整性前置——本次 run 作废、修数重跑，不得写成「策略 FAIL」。

- 灰区**不得**写成「接近通过」「基本有效」「值得进入下一步」。灰区的出口只有一个：不采用，若要继续必须新预注册。
- 判定只做一次读表，不做二次拟合；不允许为凑 P2 而改 0.25。

### 阈值来源（必须与本文件同时引用）

- `0.25`：**由涨跌幅制度推出**（主板 ±10%、创业板/科创板 ±20%，25% > 2×10%），不是从 199 笔分布里挑的，也不是回测最优值。
- `3.00pp`（P2）：**预注册拍定**——按「改善必须可感、不可拟合」取整到 3pp；不是 MDD 分布的分位数。
- `0`（P3 的 `D_k` 符号判据）：**预注册拍定**，不是拟合参数。**R2 后它的作用域收窄**：v1 把「被测臂 `T_1`/`T_5` 去尾后 > 0」当门，该门已作废（基准自身 −9.92% / −75.72%）；现在 `0` 只用作「`D_k` 正负」这条符号判据的分界，`T_1`/`T_5` 的绝对值改为报告项。**取值未变（仍是 0），变的只是它管哪件事。**
- 以上三项在写任何 run 之前固定；**本轮 N +1**（一格：`trailing_stop=0.25` 主假设）。**备选 B 不计入 N**（本轮不跑）。成本档 10bp/30bp 沿用 S01b 的 `not_counted` 口径，不计入 N。台账登记（`global_N_lower_bound 19 → 20`、假设计数 `16 → 17`）由因子研究员按其口径执行，**我不代登记、不代改台账**。

## ③ 引擎能力判定（只读代码，未改任何文件）

### 3.0 结论（一句话，可直接引用）

**可表达。** 现有引擎已有原生字段 `trailing_stop`（peak 基准的百分比回撤止损），六键 `overrides` 在 API → `MatcherConfig` 链路上**确实被读取并落到撮合配置**。S01c 主假设不需要任何新能力。

**peak 口径不是传参项（R5）**：`overrides` 只读 stop_loss / take_profit / trailing_stop / trailing_take_profit_activate / trailing_take_profit_drawdown / max_hold_days 六键（`strategy.py:1601-1622`）；`trailing_peak_price` 只来自策略文件的 `META.backtest_defaults`（当前生产文件第 58 行 = `"close"`；解析 `execution_policy.py:135-140`，落地 `strategy.py:1865`），**请求里传了会被静默忽略**。它决定「峰值取收盘还是最高价」，只能改文件改；决策只用截至前一交易日的峰值（不含当日），无前视。

### 3.1 六键 overrides 的读取与落地（逐项，实测）

| 键 | 读取位置 | 落地字段 | 语义/钳制 |
|---|---|---|---|
| `stop_loss` | `strategy.py:1601` | `MatcherConfig.stop_loss_pct`（`:1850`） | 原值直传，**无钳制**；符号用 `abs()`。写成 `-8` 会被 `validate_risk_scale` 在请求层 422（`risk_limits.py:37-42`）；`-0.08` 合法 |
| `take_profit` | `strategy.py:1602-1606` | `:1851` | `_normalize_pct` 钳 [0.01, 5.0] |

| `trailing_take_profit_activate` | `strategy.py:1612-1616` | `:1853` | 钳 [0.01, 2.0]；**只门控移动止盈，不门控移动止损** |

### 3.2 peak 口径与建仓当日 high（关键，实测）

生产路径走 `_simulate_portfolio_matrix`（`engine.py:2578`；入口 `:2541`/`:2576`）：

- 峰值字段：`pos["max_high"]` 与 `pos["max_close"]` 在**建仓时都初始化为成交价**（`engine.py:3421-3422`）。
- **入场价口径 = raw 且矩阵有 `raw_close` ⇒ `legacy_raw_risk=True`（`:2588-2590`）、`raw_execution` 非空（`:2591-2607`）**；此时 `_trailing_risk_line` 走第一分支，直接返回 `adjusted_peak × (1−|drawdown|)`（`:3019-3023`）。
- **peak=close 的选择点**：`config.trailing_peak_price == "close"` 时用 `pos["max_close"]`，否则 `pos["max_high"]`（`:3067-3071`、`:4021-4025`）。生产文件已声明 `trailing_peak_price="close"`（第 58 行），`MatcherConfig` 默认是 `"high"`（`:253,362`）——**规格依赖文件声明，请求不改这一项**。
- **更新时点**：每日**收盘后**并入当日 `execution_close`（`:4305-4307`），`max_high` 只在满足 `high_counts_for_peak` 时并入（`:4295-4304`）；决策在收盘之前（开盘段 `:3951-3986`、日内段 `:4003-4077`），所以**当日峰值不参与当日决策**（`:4001-4002` 注释原文：「风控线使用截至上一交易日的峰值 … 不引入未来数据」）。
- **建仓当日 high 是否计入**：close 口径下**不使用** `max_high`，因此 entry-day high 与本假设无关；entry-day **收盘价计入** `max_close`（`:4305-4307`，无 entry-day 例外），即次日首条风控线的 peak = `max(entry_price, 建仓日收盘)`。
- **建仓当日能否被止损**：不能。开盘段与日内段都跳过 `pos["entry_date"] == date_text`（`:3863-3864`、`:4007-4010`），收盘段建仓日分支只做「登记次日退出计划」（`:4120-4152`）。即 **T+1 起才可能触发移动止损**。

### 3.4 `exit_reason` 枚举与优先级（实测）

- 枚举：`"signal" | "stop_loss" | "take_profit" | "trailing_stop" | "trailing_take_profit" | "max_hold" | "end"`（`engine.py:420`）；**优先级注释**在 `:421`：「pending_exit(历史挂单) > 风控(止损/移动止损/移动止盈) > signal(卖点) > max_hold(到期) > end」。
- 同日多风控线取**价格最高**的一条（最紧）：`max(valid_lines, key=价格)`（`:3111`、`:4056`）；本规格只有 `trailing_stop` 一条线，不存在并列。
- 同日 `signal` 与风控同时成立：风控段先执行并 `continue`，signal 不再改写原因（`:4068-4077` 后进入 `:4139` 段时该持仓已出表）。
- `max_hold` 判定在 signal 之后（收盘段 `:4173-4267`：signal 在 `:4175-4184`，`elif config.max_hold_days …` 在 `:4258`），因此与规格 §1.4 一致。

### 3.5 「可表达」的字段级答复（可直接抄给开发/评审）

- 字段名：`overrides.trailing_stop`（小数比例）＋ 策略声明 `META.backtest_defaults.trailing_peak_price="close"`。
- 生效位置：`backend/app/backtest/strategy.py:1607-1611`（读取/钳制）→ `:1852`（`MatcherConfig.trailing_stop_pct`）→ `backend/app/backtest/engine.py:3077-3087`（开盘段线价）、`:4029-4039`（日内段线价）、`:3012-3055`（线价换算）、`:4058-4067`（成交价规则）。
- 语义：**何时触发**——建仓日之后的每个交易日，用「截至前一交易日收盘的 `max_close` × 0.75」作线；开盘价 ≤ 线即在开盘成交（跳空按开盘价），否则盘中 `low ≤ 线` 即按线价成交；拒卖（停牌/跌停）时挂单顺延到下一可卖日。**按什么价成交**——跳空=开盘价，盘中触及=线价，两者都再扣 10bp 滑点；顺延单按次一可卖日的 `exit_fill` 价。

### 3.6 表达不了的能力（单列，**不阻塞本轮**；按裁定 §6 的处理方式交开发经理排期）

1. **带「盈利激活门槛」的移动止损**：`trailing_take_profit_activate` 只门控移动止盈线，且必须与 `trailing_take_profit_drawdown` 同时存在才生效（`engine.py:3088-3095`、`:4040-4053`，条件 `activate is not None and drawdown is not None`）。想表达「浮盈 ≥ X% 才启用 25% 移动止损」时，只能借道移动止盈，但那会**引入第二条风控线**，语义不同。最小能力需求：`trailing_stop_activate_pct`（输入：小数比例；输出：仅在 `peak/entry−1 ≥ X` 时把 `trailing_stop` 线加入 `risk_lines`；生效位置 `engine.py:3077-3087`、`:4029-4039`）。
2. **「收盘确认」的移动止损**：peak 可取收盘（本规格已用），但触发与成交一律按盘中 `low`/开盘价（`:4058-4067`），**没有「收盘跌破才出场、次日开盘成交」的开关**。本轮不需要（规格就是盘中触发），但它意味着 S01c 的读数不能解释为「收盘确认式止盈止损」。
3. **按线价挂单穿透跌停**：跌停/停牌一律顺延（`:3127-3145`），无「按线价强平」模式；这会系统性高估止损的成交质量（只能顺延到更低价），属**已知向下的偏差方向**，必须在结果解读时写明，不允许当作「止损无效」的证据。
4. **口径不一致（引擎内部事实，非本轮阻塞）**：单标的独立路径 `_simulate_independent_matrix`（`:1544-1921`）**忽略 `trailing_peak_price`**——`:1709` 直接取 `pos["max_high"]`、`:1901` 只用 `matrix.high` 更新，且其 `pos` 字典（`:1849-1875`）没有 `max_close` 键。同一份 `MatcherConfig` 在两条路径上会得到 high-peak 与 close-peak 两种读数。S01c 走持仓账户路径（`:2578`），不受影响；此为 P3 级记录项。
5. **部分止盈/分批减仓**：`_sell` 全平（`:3177-3233`），不可表达；本轮不需要。
