# 交割单台账 字段与口径字典

版本 `parser 1.0.0` / `derive 1.0.0`（2026-11-07）。任何口径修改都要改版本号并在本文追加变更记录。

适用范围：本系统内所有「按交割单还原真实交易过程」的复盘、归因、对账。**不用于策略信号生成与回测。**

---

## 1. 输入：券商交割单 CSV

| 特征 | 处理方式 |
| --- | --- |
| 编码 | 依次探测 BOM → UTF-8 → GB18030；本单实测 `gb18030` |
| 表头前的空行、表尾空行 | 跳过，计入 `rows_skipped`（本单 0 行） |
| 脏格式 `= "600000      "` | 还原为 `600000`（去等号引号与定宽补空格），否则代码/名称匹配全错 |
| `--`/`-`/`空` | 归一为空值，金额按 0 处理，不参与计算 |
| 行序 | 券商按时间**倒序**导出；入库前按 (发生日期, 发生时间, 成交编号) 正序稳定排序 |
| 发生日期为空 | 回落交收日期，并记 warning（本单第 792、793 行，2025-09-04 台账划转） |

去重键 `event_uid`：

- 有成交编号：`{发生日期}|{发生时间}|{成交编号}`；
- 转账/利息等无成交编号的行：整行规范化内容的 sha1 前 16 位。

因此同一文件重复导入 `rows_new = 0`，跨批次导出（券商不改成交编号）也不会重复。

## 2. 事件分类（`event.category`）

| 原始「交易类别」 | category | 现金流符号 | 计权益 | 计入净入金 | 计入其他损益 |
| --- | --- | --- | --- | --- | --- |
| 证券买入 | `trade_buy` | − | 是 | 否 | 否 |
| 证券卖出 | `trade_sell` | + | 是 | 否 | 否 |
| 银行转证券 | `deposit_in` | + | 是 | **是** | 否 |
| 证券转银行 | `deposit_out` | − | 是 | **是** | 否 |
| 台账间现金划转取/存 | `internal_out` / `internal_in` | −/+ | 是 | 否（内部搬运，净额 0） | 否 |
| 配售缴款 | `allocation_pay` | − | 是 | 否 | 否（作为转债成本） |
| 新股入账 | `security_in` | 0 | 是（只加股数） | 否 | 否 |
| 红利入账 | `dividend` | + | 是 | 否 | **是** |
| 股息红利差异扣税 | `dividend_tax` | − | 是 | 否 | **是** |

## 3. 账户级口径（关键）

1. **现金** = Σ `发生金额`。发生金额已含佣金、过户费、印花税，**不再二次扣费**。
2. **权益** = 现金 + Σ(持仓数量 × 当日不复权收盘价)。
3. **期初现金** = 0.02 元（本单首日「利息归本」0.02 元，按首日权益反推）。
4. **累计净入金** = Σ(`deposit_in` + `deposit_out`)，本单 92,073.93。
   台账间划转不计入净入金（左右各 10,000，净额 0）。
5. **累计盈亏** = 权益 − 累计净入金 − 期初现金，本单 −75,824.59。
6. **`资金余额` 栏不可用于对账**，原因两条：
   - 该栏是逐笔事件的即时余额，含 T+1 在途（卖出款次日才入账），不等于当日可用现金；
   - 2025-09-04 发生过一次**台账切换**：`台账间现金划转取 −10,000`（余额归 0.00）后紧接
     `台账间现金划转存 +10,000`（新台账余额 10,758.03）。新台账继承了 758.03 元期初余额，
     而这笔钱没有任何发生金额记录。
   - 数量级：切换行 10,758.03 与累计发生金额 44.34 相差 **10,713.67 元**；文件最新一笔
     （2026-11-06 14:53:24 证券转银行）余额 1,937.57 与累计发生金额 44.34 相差 **1,893.23 元**。
     两个差额都不能靠该栏修正，所以权益只认"Σ发生金额 + 持仓市值"。
7. **价格源**：`D:\TSP\data\kline_daily`（原始日线，不复权，逐日分区）优先；
   某日分区整体缺失时才取 `kline_daily_enriched`（前复权）补缺（本单仅 2026-10-26 一天）。
   明细里 `price_src` 记录来源：`close` / `ffill` / `last_trade` / `missing`。
   行情库未收录的 ETF/转债退化为该代码最后一次成交价，并标 `last_trade`。
8. **交易日轴**：行情库 `date=YYYY-MM-DD` 分区（K 线轴），不用自然日历；`hold_td` 按该轴计。
9. **价格缺失保护**：派生前会检查价格簿覆盖度，`summary.json.prices` 记录 `codes/days/day_min/day_max/mode`。
   若价格 0 条（典型原因：用了没装 polars 的系统 python），派生直接报错退出，
   不产出"持仓市值全 0、权益只剩现金"的错表；确认要试跑才加 `--allow-no-prices`。
   本单正常覆盖：132 个代码 × 396 个交易日。

## 4. 派生表 `roundtrip`（FIFO 回合）

| 字段 | 含义 |
| --- | --- |
| `code` / `name` / `kind` | 证券代码、名称、类别 |
| `open_time` | 买入成交时间；无买入来源时为空 |
| `close_time` | 卖出成交时间 |
| `qty` | 本条回合消耗的股数（一笔卖出可拆成多行） |
| `buy_px` | 买入含费单价（发生金额绝对值/数量） |
| `sell_px` | 卖出含费单价（(成交金额−费用)/数量） |
| `cost` | `qty × buy_px` |
| `pnl` | `qty × (sell_px − buy_px)`；无成本时为空 |
| `ret` | `pnl / cost` |
| `hold_days` | 自然日差（向下取整） |
| `hold_td` | 交易日差（行情库轴，不含开仓日） |
| `unmatched_qty` | 该卖出中没有买入来源的股数 |
| `flags` | `unmatched_sell` = 成本按配售缴款推算；空 = 完整配对 |

**配对规则**：卖出按买入时间先后逐笔消耗（FIFO）。同一笔卖出跨多个买入批次时拆成多行，
因此"回合数"≠"卖出笔数"。

**转债特例**：可转债配售是两行不同代码 —— `配售缴款`（发债代码 75xxxx/37xxxx，现金 −×100 元/张）
与 `新股入账`（转债代码 113708/123287…，现金 0）。FIFO 无法自然配对，派生层用
(发生日期, 数量, 名称前两字) 把缴款成本挂到转债上，产出 6 条 `unmatched_sell`。
`新股入账`本身**不生成回合**（它不是平仓）。

## 5. 派生表 `daily_equity`

| 字段 | 含义 |
| --- | --- |
| `date` | 交易日 |
| `equity` | 收盘权益 = `cash + mv` |
| `mv` | 持仓市值 |
| `cash` | 累计现金（含期初 0.02） |
| `dep` | 当日外部净入金 |
| `cumdep` | 累计外部净入金 |
| `pnl` | `equity − cumdep − 期初现金` |
| `npos` | 持仓只数（数量 > 0） |

`daily_position`（每票每日）：`qty`、`cost`（**剩余持仓的 FIFO 成本**，与 `roundtrip`
同一配对口径）、`price`、`price_src`、`mv`、`upnl`（= mv − cost）、`equity`。
用 FIFO 而不是平均成本的目的是：`已实现回合盈亏 + 剩余持仓浮盈 + 其他损益` 能严丝合缝地
拼回权益口径盈亏（本单残差 −0.01 元）。
`exposure`：单票权重 = `mv / equity`；`industry_exposure`：按产业链一级分类汇总，
代码不在图谱中标 `未分类`。

## 6. 绩效指标定义（`summary.json.performance`）

| 指标 | 定义 |
| --- | --- |
| `roundtrips_paired` | 完整配对回合数（本单 435），**所有胜负统计的分母** |
| `roundtrips_unmatched_sell` | 无买入来源、成本推算的回合（本单 6），单列 |
| `pnl_realized` | 配对回合盈亏合计（−79,597.28） |
| `pnl_unmatched_est` | 推算回合盈亏合计（+3,374.82） |
| `pnl_total_est` | 两者合计（−76,222.46），与权益口径的差由浮盈/红利/利息解释 |
| `win_rate` | 盈利回合 / `roundtrips_paired`（42.07%） |
| `payoff` / `profit_factor` | 平均盈利÷平均亏损 / 总盈利÷总亏损绝对值 |
| `expectancy` | 配对回合盈亏均值（元/回合） |
| `avg_ret` | 配对回合 `ret` 均值 |
| `hold_median_td` | 交易日持仓中位数 |
| `turnover_x` | (买入额+卖出额) / 平均权益 |
| `fee_ratio` | 费用 / 平均权益 |
| `max_drawdown` | 权益回撤峰值；**只取权益 ≥1,000 元的交易日**，避免期初 0.04 元把回撤算成 100% |
| `max_drawdown_raw` | 不设门槛的原始回撤（保留供核对，97.99%→99.99%） |

`pnl_bridge`（`stats` 子命令）把权益口径盈亏拆成：配对回合盈亏 + 未配对卖出净额 −
推算成本 + 其他损益（红利/利息/投顾费）+ 期末浮盈，残差应接近 0（本单 −0.01 元）。
注意：未配对回合的盈亏不再计入"已实现"，否则会与"净额 − 成本"重复计算
（这一条是 2026-11-07 修正的，修正前桥接残差 −2,936.95 元）。

## 7. 对账表 `reconcile.csv`（每日复盘产物）

实际列由系统填满，计划/信号列留空或有信号文件时回填，**偏离列由决策侧填写**：

| 列 | 谁填 | 说明 |
| --- | --- | --- |
| `date` `time` `code` `name` `side` | 系统 | 实际成交 |
| `actual_qty` `actual_px` `actual_amt` `fees` | 系统 | 实际数量、含费单价、成交金额、费用 |
| `signal_id` `plan_time` `plan_side` `plan_qty` `plan_px` | 系统回填 | 来自 `--signals` 文件（列：date,time,code,side,qty,px,signal_id） |
| `deviation_type` | 决策侧 | 建议枚举：按时 / 迟到 / 未成交 / 超量 / 减少 / 反向 / 无计划 / 手工 |
| `deviation_reason` | 决策侧 | 自由文本，写"为什么"，不写"是什么" |
| `link_status` | 系统 | `matched`（同日同码同向有信号）/ `no_signal`（无信号，需决策侧确认是否漏记） |
| `note` | 决策侧 | 备注 |

没有信号文件时全部为 `no_signal`，这是空表的正常形态，不是错误。

## 8. 已知限制

1. 交割单只有成交与资金流水，没有委托/撤单记录：**未成交、部分成交、撤单无法还原**，
   只能通过 `reconcile` 的 `no_signal` 与计划侧比对间接发现。
2. 转债成本为推算值（100 元/张 + 0 费用），实际缴款费用若存在会带来分角级误差。
3. 期初现金按首日权益反推（0.02 元）；若换账户/换券商，需用 `--opening-cash` 显式指定。
4. `kline_daily_enriched` 是前复权口径，仅在原始日线缺分区时兜底；若补的日期恰好有除权，
   当日市值会与原始口径不一致（本单无此情况，可用 `price_src` 复核）。
5. 行业分类来自 `industry_chain/graph.json` 的当前版本，不回看历史版本，历史暴露的行业归属
   以图谱当前状态为准。
