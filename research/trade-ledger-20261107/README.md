# 交割单台账（trade_ledger）

把券商导出的交割单 CSV 变成可回放、可对账、可复算的台账与派生表，供每日复盘调用。
属于**过程记录与可追溯**层：只读交割单与行情，不改策略、不改因子、不碰下单。

- 代码：`research/trade-ledger-20261107/tsp_ledger/`
- 库：`<data-root>/user_data/trade_ledger/ledger.sqlite`（默认 data-root 为 `D:\TSP\data`）
- 字段与口径：`docs/FIELD_DICT.md`
- 每日复盘用法与自动化路径：`docs/DAILY_WORKFLOW.md`
- 基准比对报告：`out/verify_default.json`、`out/verify_compat.json`

## 1. 四步跑通

**必须用后端虚拟环境跑**（`polars` 只装在那里）。用系统 python 会出现"价格 0 条 → 持仓市值全 0"：
现在派生入口会直接报错而不是静默出表，确实要在无行情的环境试跑才加 `--allow-no-prices`。

```bash
PY=backend/.venv/Scripts/python.exe        # 用系统后端的虚拟环境（含 polars）

# 1) 导入（幂等；同一文件重复导入不产生新行）
$PY -m tsp_ledger.cli import <交割单.csv>

# 2) 重建派生表 + 导出 CSV（回合 / 日频权益 / 持仓 / 暴露）
$PY -m tsp_ledger.cli derive --out out

# 3) 某交易日的复盘包（可同时把当天新导出的交割单带进来）
$PY -m tsp_ledger.cli daily --date 2026-11-06 --file <当日交割单.csv> --out out/daily

# 4) 与临时基准目录逐字段比对
$PY -m tsp_ledger.cli verify --baseline ../jiaogedan-review-20261107/data --out out
```

在 `research/trade-ledger-20261107` 目录下执行。

## 3. 与临时基准的 6 行差异（可解释，不是丢数据）

基准 447 = 435 完整配对 + 6 笔转债卖出（pnl 为空）+ 6 笔「新股入账」伪卖出（0 价、pnl 为空）。
正式口径 441 = 435 完整配对 + 6 笔转债卖出（按配售缴款成本 100 元/张推算 pnl，标 `unmatched_sell`）。

- 「新股入账」是证券到账（发生金额 0），不是平仓，因此不再生成伪回合；这是基准口径的缺陷。
- 6 笔转债卖出的买入来源确实不存在：缴款记在发债代码（75xxxx/37xxxx），到账记在转债代码
  （113708/123287…），FIFO 无法自然配对。正式口径用 (发生日期, 数量, 名称前两字) 把
  缴款成本挂过去，pnl 为推算值并标 `unmatched_sell`，不进胜率分母。
- 若需与历史基准严格逐行对齐，用 `--compat`：447 行、键集合完全一致、逐字段 pnl 0 差异。

## 4. 落库

`D:\TSP\data\user_data\trade_ledger\ledger.sqlite`（WAL），已用本单实跑落库（1.5 MB）。表：
`import_batch`（文件哈希、编码、行数、去重结果）、`event`（事件级，主键 `event_uid`）、
`roundtrip`、`daily_equity`、`daily_position`、`exposure`、`meta`。
派生的四张表按批次全量覆盖，可随时用同一份事件重建；事件表只增不重。
导出与验证报告在 `user_data\trade_ledger\exports\`，每日复盘包在 `user_data\trade_ledger\daily\<date>\`。

## 5. 边界

- 只读 `D:\TSP\data\kline_daily`（不复权收盘价）与 `kline_daily_enriched`（补缺日），不写行情库。
- 不改回测引擎、WFO、行情新鲜度、复权与信号生成；不做策略设计与因子实现；不下单。
- 交割单里的「资金余额」栏不可用于对账（T+1 在途 + 一次台账切换），权益一律按
  Σ发生金额 + 持仓市值计算，详见 `docs/FIELD_DICT.md` §3。
